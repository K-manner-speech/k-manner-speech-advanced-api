## 1. 작성 범위와 기준

### 1.1 Figma 참조 범위

- 파일: `K-manner-speech-advanced` (`G8GxBvtJDcALvKcGvaSHhH`)
- 단일 기준 페이지는 `01 Screen Plan 1.2.0` (`1169:2`)이다.
- 페이지의 `01 인증 / 온보딩`, `02 홈 화면 / 선택`, `03 대화 연습`, `04 면접 연습`, `05 결과 복습`, `06 내 정보`, `07 대화방 목록`을 포함한다.
- 화면 ID와 화면명은 Figma 최상위 프레임 이름을 그대로 사용한다. 문서에만 존재하고 Figma 1.2.0에 없는 별도 화면 ID를 새로 만들지 않는다.
- 화면 배치 화살표와 상태별 프레임은 화면 간 이동, 선택 전·후, 완료와 팝업 동작의 근거로 사용한다.
- 색상·타이포그래피·간격·버튼·입력 규격은 `docs/DESIGN_SYSTEM.md`의 Screen Plan 1.2.0 토큰을 따른다.

### 1.2 확정된 제품 기준

이 문서는 사용자가 보는 화면, 행동, 상태와 복구 경험을 정의한다. API 요청·응답, 멱등성, 데이터베이스 유일성, 레코드 갱신과 물리 삭제 순서는 각각 `docs/API명세.md`, `docs/ERD.md`, `docs/아키텍처.md`를 단일 기준으로 삼는다. 아래에 언급된 기술 상태는 화면 표시와 전이 판단에 필요한 최소 의존성이지 백엔드 구현 명세가 아니다.

- 음성 입력은 자동 전송하지 않는다. 녹음을 마치면 STT 결과를 입력창에 넣고, 사용자가 확인하거나 고쳐서 직접 보낸다. 전송된 음성 메시지에는 `음성 입력` 라벨과 다시 듣기 행동을 제공한다.
- 면접 연습은 `I09 음성 전사 확인`에서 전사 결과를 확인·수정한 뒤 명시적으로 전송한다.
- 면접 연습에서 이력서는 필수다. 이력서 없이 공통 질문으로 진행하는 경로는 제공하지 않는다.
- 업로드 규격은 디자인 시스템과 동일하게 이력서 PDF 10MB 이하(필수), 포트폴리오 PDF 10MB 이하(선택), 자기소개서 DOCX 10MB 이하(선택)로 한다.
- 평가 항목은 `높임법`, `예의와 배려`, `상황 적합성`, `자연스러움`으로 통일한다.
- 면접 피드백은 `질문 이해·적합성`, `답변 구조`, `구체성·근거`, `직무 적합성·문제 해결력`, `전달력·태도`의 다섯 평가 항목으로 제공한다. 각 항목은 1~5점으로 평가하며, AI는 답변에 실제로 드러난 내용만 근거로 판단한다.
- 페르소나 감정 상태는 `neutral`, `happy`, `sad`, `angry`, `curious`, `embarrassment` 여섯 가지다.
- 온보딩은 계정 생성, 프로필 입력, UI 언어 선택으로 구성한다.
- 프로필의 `이름`, `나이`, `성별`, `모국어`, `UI 언어`는 모두 필수다. 미입력 상태로 온보딩을 완료할 수 없다.
- A01~A05 인증·온보딩의 핵심 안내와 행동만 한국어·영어를 병기한다. H01 이후 화면은 사용자가 선택한 표시 언어 하나만 사용한다.
- 면접 결과는 합격·불합격을 판정하지 않는다. 답변 내용, 전달 방식, 강점, 보완점과 다음 연습을 코칭한다.
- 사용자는 진행 중인 자유채팅, 기본 상황 시나리오와 면접을 직접 종료할 수 있다.
- 면접도 중간 종료를 제공한다. 남은 질문을 다 채우지 못해도 지금까지의 답변으로 결과를 만든다. 답변을 남긴 채 그만두는 사람에게 아무 기록도 주지 않는 편보다 낫다.
- 화면을 나가는 것은 종료가 아니다. 나가도 `in_progress`로 유지하고 다시 들어오면 다음 미답변 질문부터 이어간다.
- 기본 상황 시나리오가 제한 턴 전에 목표를 이루면 곧바로 끝내지 않고 종료할지 이어갈지 사용자에게 묻는다.
- 면접 화면을 나가더라도 면접을 완료 처리하지 않고 `in_progress` 상태로 유지하며, 다시 진입하면 다음 미답변 질문부터 이어간다.
- 화면 나가기, 연습 종료와 대화방 삭제는 서로 다른 행동으로 제공한다.
- 목표 달성 후 사용자가 종료를 선택한 경우, 최대 턴 도달, 면접 완료와 사용자 종료는 대화방 상태를 `completed`로 전환하고 종료 원인을 별도로 기록한다.
- 사용자가 자유채팅 또는 기본 상황 시나리오를 종료한 경우에도 종료 시점까지 저장된 사용자 발화를 기준으로 종합 피드백을 생성한다.
- 종료된 대화방은 대화방 목록에서 선택하여 읽기 전용으로 다시 확인할 수 있다.

## 2. 공통 화면 규칙

### 2.1 앱 셸과 내비게이션

- 모바일 화면은 360px 기준 단일 컬럼 정보 구조를 사용한다.
- 반응형 구간은 Mobile `0~767px`, Tablet `768~1199px`, Desktop `1200px 이상`으로 구분한다.
- Mobile은 화면 폭 전체를 사용하고, Tablet은 앱 셸 최대 560px, Desktop은 앱 셸 최대 1200px로 중앙 정렬한다.
- Tablet은 단일 컬럼을 유지하며, Desktop에서만 대화 중심 컬럼과 보조 정보 패널을 나란히 배치한다.
- 하단 내비게이션은 `홈`, `연습`, `대화 목록`, `내 정보` 네 영역을 제공한다.
- 상세 화면의 뒤로가기는 직전 화면으로 이동하고 입력 중인 값은 가능한 한 보존한다.
- 데스크톱에서는 같은 정보 구조를 유지하되 앱 셸을 중앙에 배치하고 보조 정보만 좌우 패널로 확장한다.
- 모바일 가상 키보드가 열리면 입력 영역을 키보드 위에 고정하고 메시지 영역 높이만 줄인다. 하단 내비게이션은 키보드가 열린 동안 숨기며 작성 중인 텍스트와 스크롤 위치를 유지한다.
- 비로그인 사용자는 A01 스플래시, A02 로그인, A03 회원가입, A04 프로필, A05 언어 선택의 인증·온보딩 흐름만 접근할 수 있다.
- H01 이후 홈·연습·대화·결과·내 정보·대화방 목록 화면과 관련 데이터 API는 모두 인증된 사용자만 접근할 수 있다.
- 인증되지 않은 사용자가 보호 화면 또는 API를 요청하면 데이터를 반환하지 않고 A02 로그인으로 안내한다.
- 보호 화면 이용 중 인증 세션이 만료되면 현재 요청을 중단하고 A02 로그인으로 이동한다.
- 세션 만료 시 아직 전송·저장하지 않은 텍스트, 음성 전사, 프로필 수정값과 파일 선택 상태를 브라우저 또는 서버에 임시 보존하지 않는다.
- 로그인 화면에는 세션 만료와 미저장 입력이 보존되지 않았음을 명확하게 안내한다.
- 세션 만료 후 재로그인에 성공하면 이전 화면으로 복귀하지 않고 항상 H01 홈으로 이동한다.
- 대화 화면의 뒤로가기와 하단 내비게이션 이동은 연습 종료로 처리하지 않는다.
- 진행 중인 대화 화면을 나가면 대화방은 `in_progress`를 유지하며 대화방 목록에서 이어갈 수 있다.
- `종료`는 진행 중인 자유채팅·기본 상황 시나리오 화면의 상단 오른쪽에서 제공하며 사용자 확인 후 실행한다.
- 목표 달성 안내 카드나 면접 종료 카드가 떠 있을 때는 그 안에 이미 종료 행동이 있으므로 상단 `종료`를 함께 내지 않는다.

### 2.2 입력·피드백

- 빈 값과 공백만 있는 텍스트는 전송하지 않는다.
- 음성은 연습 종류와 상관없이 `녹음 → 전사 확인·수정 → 보내기` 순서로 처리한다. 일반 대화는 입력창에서 고치고, 면접은 인식된 답변 카드에서 `다시 녹음`과 `이 답변 전송` 중 하나를 고른다.
- AI 응답 텍스트를 먼저 표시하고 TTS 자동 재생을 시도한다. 자동 재생 차단 또는 실패 시 다시 듣기 행동을 제공한다.
- 발화 피드백은 잘한 점을 먼저 제시하고 문제 이유, 추천 표현과 다시 말하기 행동을 함께 제공한다.
- 감정 분석은 `AI가 추정한 감정과 인상`으로 표현하고 사실처럼 단정하지 않는다.
- 발화 전송을 시작하면 해당 입력의 보내기 버튼과 중복 전송 동작을 비활성화하고 처리 상태를 표시한다.
- 클라이언트 재시도 키를 사용해 버튼 연속 클릭, 네트워크 재전송과 동일 요청의 중복 도착에도 사용자 메시지를 한 번만 생성한다.
- 한 사용자 발화에는 AI 응답을 한 번만 연결하며 중복 요청으로 턴 수를 증가시키지 않는다.

### 2.3 상태·접근성

- 로딩, 빈 상태, 오류, 시간 초과와 부분 성공에는 현재 작업과 다음 행동을 텍스트로 알린다.
- 오류가 발생해도 사용자 입력과 이미 성공한 결과를 보존한다.
- 터치 대상은 최소 44×44px, 공용 Primary/Secondary 버튼은 52px 높이를 기본으로 하며 일반 텍스트 대비는 4.5:1 이상을 목표로 한다.
- 선택 상태는 테라코타 테두리와 배경 변화에 더해 라벨·체크 또는 버튼 활성화로 함께 알린다.
- 상태·감정·점수는 색상만으로 구분하지 않고 라벨, 아이콘 또는 수치를 함께 사용한다.
- 음성에는 동일한 텍스트를, 페르소나 이미지에는 역할과 감정을 설명하는 대체 텍스트를 제공한다.
- 모달과 바텀시트가 열리면 제목 또는 첫 번째 안전한 행동으로 포커스를 이동하고 내부에 포커스를 가둔다. `Esc`와 명시적 닫기 행동을 제공하며 닫힌 뒤에는 실행한 트리거로 포커스를 돌려보낸다.
- 파괴적 확인 모달의 초기 포커스는 취소 버튼에 둔다. 오류 입력은 `aria-invalid`와 `aria-describedby`로 오류 문구에 연결하고 첫 오류 필드로 포커스를 이동한다.

### 2.4 시각 시스템 적용

- 앱 배경은 웜 아이보리 `#FFF8F0`, 기본 CTA·활성 내비게이션·진행 상태는 테라코타 `#C85F4A`를 사용한다.
- 제목은 `#35231F`, 본문·설명은 `#5D4942` 또는 `#81675F`를 사용하고 흰색 카드는 배경과 테두리로 구분한다.
- 기본 Primary 버튼은 높이 52px, 모서리 12px, 좌우 패딩 16px이다. 눌림은 `#A84737`, 비활성은 `#F1DFD8` 배경과 `#75665E` 라벨을 사용한다.
- 입력창은 높이 48px, 모서리 12px이며 기본 1px `#D4BFB5`, 포커스 2px `#C85F4A`, 입력 완료 1px `#B29485`, 오류 2px `#B82E26` 테두리를 사용한다.
- 카드 모서리는 14~16px, 주요 패널은 24px을 사용한다. 아이콘·아바타·더보기 등 독립 행동에는 최소 44px 터치 영역을 확보한다.
- 기본 글꼴은 `Noto Sans KR`이며 한국어가 섞이지 않은 영문 버튼에만 Figma 지정에 따라 `Inter`를 허용한다.
- 하단 내비게이션은 360px 화면에서 4개 항목을 각각 90px 폭, 전체 높이 58px로 배치한다.

## 4. 01 인증·온보딩

| ID | 화면 | 목적과 주요 요소 | 핵심 동작·이동 |
| --- | --- | --- | --- |
| A01 | 시작 | 브랜드 마크, 대화 말풍선 히어로, 한국어·영어 가치 제안, 시작 CTA | `시작하기 · Get started` → A02 |

## 6. 03 대화 연습

### 6.1 공통 구성

- 상단: 뒤로가기, 대화 목표, 페르소나 이름·관계, `종료`.
- 페르소나 영역: 동일 인물의 여섯 감정 이미지와 텍스트 감정 라벨.
- 대화 영역: AI·사용자 메시지, 입력 출처, TTS 상태, 피드백 보기.
- 하단: 여러 줄 텍스트 입력, 마이크, 보내기, 하단 내비게이션.
- `종료`는 연습 종류와 상관없이 `in_progress`일 때 제공한다. 면접도 포함한다. 누르면 무엇을 잃는지 알린 뒤 한 번 더 확인받는다. 되돌릴 수 없기 때문이다.
- 한 번도 답하지 않은 방은 종료해도 `completed`로 넘기지 않는다. 만들 결과가 없어 빈 결과만 남는다.
- 기본 상황 시나리오가 제한 턴 전에 필수 성공 조건을 채우면 대화방은 `in_progress`를 유지하고 UI 하위 상태만 `goal_achieved_pending_choice`로 전환한다. 목표 달성 카드를 띄우고 사용자가 `연습 종료` 또는 `계속하기`를 고를 때까지 보내기와 마이크를 잠근다. 입력창 자체는 잠그지 않아 쓰던 문장을 잃지 않는다.
- `연습 종료`를 선택한 때에만 `completed/goal_achieved`로 확정한다. `계속하기`를 선택하면 `in_progress`로 돌아가며 같은 목표 달성 카드는 다시 띄우지 않고 최대 턴 또는 사용자 종료까지 진행한다.
- `completed` 상태의 읽기 전용 화면에서는 입력창, 마이크와 보내기 행동을 제공하지 않는다.

### 6.1.1 대화 맥락 구성

- AI 응답 생성에는 같은 대화방의 전체 대화를 맥락으로 사용한다.
- 전체 원문이 모델 입력 한도를 넘으면 오래된 메시지부터 요약하고 최근 메시지는 가능한 한 원문으로 유지한다.
- 요약은 관계, 상황, 대화 목표, 사용자가 밝힌 사실, 이미 합의한 내용과 해결되지 않은 질문을 보존해야 한다.
- 요약 때문에 최신 사용자 발화나 최신 AI 질문이 누락되지 않도록 입력 예산에서 최근 메시지를 우선한다.
- 다른 대화방의 메시지나 요약을 현재 대화 맥락에 섞지 않는다.
- 오래된 메시지로 만든 요약은 해당 대화방의 내부 맥락 데이터로 저장해 다음 AI 응답에 재사용한다.
- 새 메시지로 입력 한도를 다시 초과하면 기존 요약과 새로 요약할 오래된 메시지를 반영해 저장된 요약을 갱신한다.
- 매 요청마다 전체 대화를 처음부터 다시 요약하지 않는다.
- 저장된 맥락 요약은 AI 입력 구성에만 사용하고 사용자 화면, 대화 이력과 피드백 목록에는 표시하지 않는다.
- 대화방을 삭제하면 저장된 맥락 요약도 연결 데이터로 즉시 영구 삭제한다.

#### C09 연습 종료 확인 규칙

- 진행 중인 자유채팅과 기본 상황 시나리오 화면에서 진입할 수 있다.
- 제목은 `대화를 종료할까요?`로 표시하고 무엇을 끝내는지 방 제목을 함께 보여 준다.
- 종료 후 새 메시지를 보낼 수 없으며, 저장된 대화를 기준으로 종합 피드백이 생성된다는 사실을 안내한다.
- 보조 행동은 `계속 연습하기`, 주요 행동은 `연습 종료`로 표시하며 대화방 삭제 확인과 같은 모달 구조를 사용한다.
- `계속 연습하기`를 선택하면 대화 상태와 입력 내용을 변경하지 않고 기존 대화로 돌아간다.
- `연습 종료`를 선택하면 중복 선택을 막고 종료 처리 상태를 표시한다.
- 종료 저장이 확정된 후 R01 결과 화면으로 이동한다.
- 종료 저장에 실패하면 C09를 닫지 않고 오류와 재시도를 제공하며 대화방을 완료된 것으로 표시하지 않는다.

### 6.4 대화 예외

- 마이크 권한 거부 또는 STT 미지원 시 텍스트 입력을 즉시 제공한다.
- STT 결과가 비어 있으면 입력창을 채우지 않고 재녹음·직접 입력을 제공한다.
- 신뢰도가 낮아도 유효한 전사 문장이 있으면 그대로 입력창에 넣어 사용자가 고칠 수 있게 한다. 전송된 뒤에는 `음성 입력` 출처와 다시 듣기를 유지한다. 면접은 I09에서 같은 기회를 제공한다.
- AI 응답 실패 시 사용자 발화를 유지하고 같은 발화 재시도를 제공한다.
- TTS 또는 감정 분석만 실패하면 AI 텍스트와 가능한 피드백을 유지한다.
- 허용되지 않은 감정값과 이미지 로드 실패는 `neutral`로 대체한다.
- 사용자 메시지 또는 AI 응답이 처리 중일 때 연습 종료를 선택하면 확인 전까지 기존 처리를 유지한다.
- 사용자가 종료를 확정하면 추가 입력과 중복 종료 행동을 차단하고 종료 처리 상태를 표시한다.
- 종료 확정 이후 늦게 도착한 AI 응답·TTS·감정 분석·발화별 피드백은 종료된 대화에 새로 표시하지 않는다.
- 종료 상태 저장에 실패하면 마지막으로 확정된 `in_progress` 상태로 돌아가며 종료 재시도를 제공한다.
- 대화 종료는 성공했지만 종합 피드백 생성에 실패한 경우 종료 상태를 되돌리지 않고 결과 화면에서 피드백 생성 재시도를 제공한다.

### 6.4.1 AI 파이프라인 부분 성공

- AI 텍스트 응답이 성공하면 TTS, 감정 분석 또는 발화별 피드백의 성공 여부와 관계없이 메시지를 즉시 저장·표시한다.
- 사용자 발화 전송이 확정된 시점부터 15초 이내에 AI 텍스트 응답이 완료되지 않으면 해당 응답 처리를 시간 초과 `failed`로 전환한다.
- AI 텍스트 시간 초과 시 사용자 메시지를 유지하고 동일 응답 레코드에 대한 재시도를 제공한다.
- 15초가 지난 기존 요청의 늦은 응답은 대화 이력에 자동 추가하지 않으며 재시도 요청과 처리 식별자를 구분한다.
- AI 텍스트, TTS, 감정 분석과 발화별 피드백은 각각 독립적인 처리 상태를 가진다.
- 각 처리 상태는 최소 `processing`, `succeeded`, `failed`를 구분하고 실패한 항목의 오류 범주와 재시도 가능 여부를 기록한다.
- TTS 실패 시 텍스트 응답과 감정·피드백 성공 결과를 유지한다.
- AI 텍스트가 표시된 시점부터 45초 이내에 TTS가 준비되지 않으면 해당 TTS 처리를 시간 초과 `failed`로 전환한다.
- TTS 시간 초과 후에도 AI 텍스트와 다른 성공 결과를 유지하고 `다시 듣기/재시도` 행동을 제공한다.
- 45초가 지난 기존 요청의 늦은 응답은 현재 음성으로 자동 연결하지 않으며, 재시도 요청과 충돌하지 않도록 처리 식별자를 검증한다.
- 감정 분석 실패 시 임의 감정을 저장하지 않고 페르소나 표시만 `neutral`로 대체한다.
- 사용자 발화 전송이 확정된 시점부터 15초 이내에 감정·인상 분석이 준비되지 않으면 해당 분석 처리를 시간 초과 `failed`로 전환한다.
- 감정 분석 시간 초과 시 감정값을 임의 생성하지 않고 페르소나를 `neutral`로 표시하며 대화와 다른 성공 결과를 유지한다.
- 15초가 지난 기존 감정 분석 요청의 늦은 응답은 현재 감정으로 자동 반영하지 않으며 재시도 처리 식별자를 검증한다.
- 발화별 피드백 실패 시 사용자 발화와 AI 텍스트 응답을 유지하고 피드백 재시도를 제공한다.
- 사용자 발화 전송이 확정된 시점부터 30초 이내에 점수와 발화별 표현 피드백이 준비되지 않으면 해당 피드백 처리를 시간 초과 `failed`로 전환한다.
- 피드백 시간 초과 후에도 사용자 메시지, AI 텍스트 응답, TTS와 감정 분석의 성공 결과를 유지하고 피드백 재시도를 제공한다.
- 30초가 지난 기존 피드백 요청의 늦은 응답은 현재 결과에 자동 반영하지 않으며 재시도 처리 식별자를 검증한다.
- 일부 항목이 실패한 경우 전체 대화를 실패로 표시하지 않고 성공한 결과와 실패 항목을 함께 표시한다.
- AI 텍스트 응답 생성이 실패해도 기존 사용자 메시지는 삭제하거나 중복 생성하지 않는다.
- AI 텍스트 재시도는 해당 사용자 메시지에 연결된 동일 응답 처리 레코드를 `processing`으로 갱신한다.
- 재시도에 성공하면 최종 AI 텍스트 응답 하나만 `succeeded` 상태로 남기고, 실패 시도별 응답 레코드는 사용자 이력에 추가하지 않는다.
- 같은 사용자 메시지의 AI 텍스트 재시도 요청도 하나의 처리로 합쳐 동시에 여러 응답이 생성되지 않게 한다.
- 실패한 TTS, 감정 분석과 발화별 피드백을 재시도할 때 새 레코드를 추가하지 않고 기존 메시지에 연결된 동일 레코드의 상태와 결과를 갱신한다.
- 재시도 시작 시 해당 항목을 `processing`으로 전환하고 성공하면 `succeeded`, 다시 실패하면 `failed`와 최신 오류 범주를 저장한다.
- 같은 메시지·처리 항목에 대한 중복 재시도 요청은 하나의 처리로 합쳐 중복 음성·분석·피드백 생성을 방지한다.
- 재시도 중에도 이전에 성공한 다른 항목의 결과는 유지한다.
- 메시지 하나에는 최종 TTS 음성 파일 하나만 연결한다.
- TTS 재시도 또는 재생성에 성공하면 새 파일 연결을 확정한 뒤 이전 음성 파일을 즉시 영구 삭제한다.
- 새 음성 생성이나 연결 저장이 실패하면 기존 음성과 연결을 유지하고 교체 완료로 표시하지 않는다.
- 이전 음성 삭제까지 확정되지 않으면 정리 작업의 실패 상태를 기록하고 중복 파일이 영구적으로 남지 않도록 재시도한다.

### 6.5 시나리오 턴과 종료 상태

- 대화방 진행 상태는 `in_progress`, `completed`를 사용한다.
- 종료 원인은 `goal_achieved`, `max_turns_reached`, `interview_completed`, `user_ended`로 구분한다.
- 기본 상황 시나리오에는 목표 달성과 최대 턴 도달 외에 사용자 종료를 제공한다.
- `max_turns`는 기본 상황 시나리오마다 별도로 설정하는 필수 양의 정수다.
- `max_turns`가 없거나 유효하지 않은 기본 상황 시나리오는 생성하거나 시작할 수 없다.
- 각 기본 상황 시나리오는 목표 달성 여부를 판단할 하나 이상의 필수 성공 조건을 가져야 한다.
- 필수 성공 조건이 없거나 유효하지 않은 기본 상황 시나리오는 생성하거나 시작할 수 없다.
- 대화 시작 전에 최대 턴 수와 필수 성공 조건을 서버에서 검증한다.
- 시나리오의 `start_message`는 선택 사항이며 별도의 첫 발화 주체 필드를 두지 않는다.
- `start_message`에 유효한 문장이 있으면 AI가 먼저 발화한다. 대화방 생성 시 첫 AI 메시지로 한 번만 저장·표시하고 턴 수에는 포함하지 않는다.
- `start_message`가 `null`, 누락 또는 공백뿐인 문자열이면 `null`로 정규화하고 사용자가 먼저 발화한다.
- 사용자 선발화 시나리오에서는 임의의 AI 시작 문장을 생성하지 않고 입력 대기 상태로 시작한다.
- 시나리오의 `1턴`은 사용자 답변 1회와 그에 대한 AI 응답 1회를 합친 단위다.
- 사용자 답변만 저장되고 AI 응답이 아직 확정되지 않은 상태는 완료된 턴으로 계산하지 않는다.
- 서버는 각 필수 성공 조건의 충족 여부와 판단 근거가 된 메시지를 기록한다.
- 모든 필수 성공 조건을 충족하면 `goal_achieved_pending_choice`를 표시하되 대화방은 `in_progress`를 유지한다.
- 사용자가 목표 달성 카드에서 `연습 종료`를 선택하면 `completed`와 `goal_achieved`로 기록한다. `계속하기`를 선택하면 목표 달성 판정은 보존하되 대화를 계속한다.
- 하나 이상의 필수 성공 조건이 충족되지 않았으면 목표를 달성한 것으로 판정하지 않는다.
- 목표를 달성하지 못한 채 최대 턴에 도달하면 `completed`와 `max_turns_reached`로 기록한다.
- 사용자가 종료를 확정하면 `completed`와 `user_ended`로 기록한다.
- 사용자 종료는 목표 달성이나 목표 실패로 표시하지 않는다.
- 사용자가 종료한 시나리오의 확인되지 않은 성공 조건은 `연습 종료 전 확인되지 않음`으로 표시한다.
- 종료 시 사용할 AI 종료 발화는 종료 원인별로 선택 사항이다.
- 해당 종료 발화에 유효한 문장이 있으면 마지막 AI 메시지로 한 번만 저장·표시하고 추가 턴으로 계산하지 않는다.
- 종료 발화가 `null`, 누락 또는 공백뿐이면 임의 문장을 생성하지 않고 종료 상태 안내와 결과·재도전 행동만 표시한다.
- `completed`로 확정된 대화에는 새 답변을 추가할 수 없으며 결과·재도전 행동을 제공한다.
- 종료가 확정되면 저장된 사용자 발화를 기준으로 종합 피드백 생성을 시작한다.
- 상태 저장에 실패하면 완료 상태를 추정하지 않고 마지막으로 확정된 `in_progress` 상태와 재시도를 표시한다.

#### 기본 상황 시나리오: 부서 팀장에게 마감 연장 요청하기

- 관계: 사용자와 부서 팀장의 업무 관계.
- 목표: 팀장에게 새 마감일까지의 일정 연장을 정중하게 요청하고 동의를 얻는다.
- 최대 턴 수: 10턴.
- 필수 성공 조건 1: 사용자가 관계에 맞는 높임법과 완곡한 표현으로 정중하게 요청한다.
- 필수 성공 조건 2: 사용자가 원하는 새 마감일을 구체적으로 제시한다.
- 필수 성공 조건 3: 대화 안에서 팀장의 연장 동의가 명시적으로 확인된다.
- 세 조건을 모두 충족하면 목표 달성 선택 카드를 표시한다. 사용자가 `연습 종료`를 선택할 때 목표 달성으로 종료하며, 종합 피드백에서도 같은 판정 근거를 사용한다.
- 팀장이 추가 설명을 요청하거나 연장을 보류·거절한 상태는 동의로 간주하지 않는다.
- 사용자가 최대 턴 전에 종료하면 `completed`와 `user_ended`로 기록하고 종료 시점까지 확인된 성공 조건과 사용자 발화를 기준으로 종합 피드백을 생성한다.
- 사용자 종료 자체를 목표 실패나 점수 감점 사유로 사용하지 않는다.

### 6.6 자유채팅 생명주기

- 자유채팅에는 최대 턴과 목표 달성 판정을 적용하지 않는다.
- 자유채팅방에는 `max_turns`를 저장하거나 적용하지 않는다.
- 자유채팅방은 생성 후 `in_progress` 상태로 시작한다.
- 화면을 나가거나 브라우저를 닫거나 로그아웃해도 상태를 변경하지 않으며, 다시 열면 저장된 메시지부터 이어간다.
- 사용자가 연습 종료를 확정하면 `completed`와 `user_ended`로 기록한다.
- 사용자 종료가 확정되면 새 메시지를 추가할 수 없으며 종료 시점까지 저장된 사용자 발화를 기준으로 종합 피드백을 생성한다.
- 종료된 자유채팅방은 대화방 목록에서 읽기 전용으로 다시 확인할 수 있다.
- 같은 페르소나로 다시 자유채팅을 시작하면 종료된 방을 재활성화하지 않고 새로운 대화방을 생성한다.
- 자유채팅방 삭제 시 종료 상태로 전환하지 않고 방과 연결 데이터를 즉시 영구 삭제한다.
- 한 사용자는 같은 페르소나와 진행 중인 자유채팅방을 하나만 가질 수 있다.
- 같은 사용자·페르소나 조합으로 자유채팅방 생성을 다시 요청했을 때 진행 중인 방이 있으면 새 방을 만들지 않고 기존 방으로 이동한다.
- 중복 요청이 동시에 발생해도 진행 중인 방이 여러 개 생성되지 않도록 서버와 데이터베이스에서 활성 사용자·페르소나 조합의 유일성을 보장한다.

### 6.7 시나리오 재도전과 결과 기록

- 같은 사용자·페르소나·시나리오 조합의 대화방이 `in_progress`이면 새 방을 만들지 않고 기존 방으로 이동한다.
- 기존 대화방이 `completed`이면 해당 방과 메시지·발화별 피드백·TTS 음성을 보존하고 새 대화방을 생성한다.
- 종료된 기존 대화방을 재도전을 위해 자동 삭제하거나 다시 `in_progress`로 변경하지 않는다.
- 종료된 대화방은 대화방 목록에서 읽기 전용으로 확인할 수 있다.
- 시나리오 시도마다 종합 결과 기록을 별도 생성한다.
- 결과 기록은 원본 대화방과 독립된 생명주기를 가지며, 사용자가 대화방을 삭제해도 유지한다.
- 결과 기록은 사용자가 피드백 목록 화면에서 직접 삭제하기 전까지 보존한다.
- 같은 종료 또는 결과 생성 요청이 중복되어도 종합 결과 기록은 시도별로 하나만 생성한다.

### 7.2 면접 대화

- 이력서 기반 면접 시나리오의 최대 턴 수는 10턴이다.
- 면접 구성은 1~10개의 필수 질문을 가져야 하며 필수 질문이 없거나 10개를 초과하면 면접을 시작할 수 없다.
- 준비된 필수 질문에 사용자가 모두 답변하고 면접관이 종료 발화를 반환하면 `awaiting_user_end` 단계로 전환한다.
- 하나 이상의 필수 질문이 미답변이면 완료로 판정하지 않는다.
- 필수 질문에 연결된 사용자 답변 메시지가 정상 저장되면 해당 질문을 `답변 완료`로 기록한다.
- 답변의 점수, 표현 품질과 피드백 성공 여부는 질문의 답변 완료 판정에 영향을 주지 않고 결과·피드백에서만 평가한다.
- 빈 값, 저장 실패 또는 질문과 연결되지 않은 메시지는 필수 질문의 답변으로 계산하지 않는다.
- 면접관이 면접 종료를 선언한 뒤에만 `면접 종료` 버튼을 표시한다. 이는 면접 도중의 중간 종료가 아니라 완료 확정 행동이다.
- 사용자가 `면접 종료`를 누르면 `completed`, `ended_reason = 'interview_completed'`로 확정하고 종합 피드백을 생성한 뒤 I11로 이동한다.
- 마지막 AI 응답 생성에 실패하면 면접을 완료로 추정하지 않고 기존 답변과 진행 상태를 유지한다.
- 면접 화면 머리에도 `종료`를 둔다. 면접관의 종료 선언을 기다리지 않고 사용자가 먼저 끝낼 수 있다. 이때는 `completed`, `ended_reason = 'user_ended'`이며, 남은 질문이 있어도 그때까지의 답변으로 종합 피드백을 만든다.
- 면접 화면의 뒤로가기와 하단 내비게이션 이동은 면접 완료로 처리하지 않는다.
- 화면을 나가면 면접방은 `in_progress` 상태를 유지한다.
- 진행 중인 면접을 다시 선택하면 저장된 마지막 답변 이후의 다음 미답변 질문부터 이어간다.
- 면접관 종료 선언 뒤 화면을 나갔다가 돌아오면 `awaiting_user_end` 상태와 `면접 종료` 버튼을 복원한다.
- 완료된 면접은 대화방 목록에서 선택하여 질문과 답변을 읽기 전용으로 확인할 수 있다.
- 완료된 면접 기록에서는 답변 입력, 녹음과 AI 응답 재시도를 제공하지 않는다.

- 포트폴리오: PDF, 최대 10MB, 선택.
- 자기소개서: DOCX, 최대 10MB, 선택.
- 업로드 전 이용 목적, 보관 기간과 삭제 방법을 안내한다.
- 업로드·분석 실패를 구분하고 파일 교체 또는 재시도를 제공한다.
- 자료 분석과 예상 질문 생성 시작 후 1분 이내에 완료되지 않으면 해당 분석을 시간 초과 `failed`로 전환한다.
- 자료 분석 시간 초과 시 업로드된 현재 파일은 유지하고 분석·질문 생성만 재시도할 수 있게 한다.
- 1분이 지난 기존 분석 요청의 늦은 결과는 현재 면접 구성에 자동 반영하지 않으며 재시도 처리 식별자를 검증한다.
- 같은 자료 버전의 분석이 시간 초과 또는 실패한 뒤 재시도되면 새 분석 레코드를 추가하지 않고 기존 실패 레코드를 `processing`으로 갱신한다.
- 동일 자료 버전의 중복 분석 재시도 요청은 하나의 처리로 합치고, 성공했을 때 기존 레코드 하나를 완료된 분석 결과로 확정한다.
- 이력서·포트폴리오·자기소개서 중 하나라도 실제로 교체되어 자료 버전이 바뀐 경우에만 새 분석 레코드를 생성한다.
- 사용자 자료와 생성 시나리오는 사용자가 삭제할 수 있어야 한다.
- 교체되지 않은 현재 이력서·포트폴리오·자기소개서 원본은 면접이 끝난 뒤에도 보존한다.
- 현재 원본은 사용자가 해당 자료를 삭제·교체하거나 회원 탈퇴를 실행할 때만 즉시 영구 삭제한다.
- 면접 완료만으로 현재 원본의 보존 상태를 변경하거나 자동 삭제하지 않는다.
- 면접 시작 전에 이력서·포트폴리오·자기소개서를 교체하거나 삭제하면 최신 자료 조합을 기준으로 새 분석과 면접 질문 생성을 처음부터 수행한다.
- 새 분석은 기존 분석 레코드를 덮어쓰지 않고 별도 레코드로 생성하며, 각 분석에 사용한 자료 버전과 생성 시각을 기록한다.
- 이전 분석 결과는 새 자료 분석 후에도 독립적으로 보존하고 피드백 목록에서 조회할 수 있게 한다.
- 이전 분석 결과는 사용자가 피드백 목록에서 직접 삭제할 때만 즉시 영구 삭제한다.
- 면접 구성에는 사용자가 최종 확인한 최신 분석과 질문만 사용하며 이전 분석 결과를 섞지 않는다.
- 자료를 교체하거나 삭제하면 이전 원본 파일은 복구 기간 없이 즉시 영구 삭제한다.
- 원본 파일 삭제 후에도 이미 생성된 이전 분석 결과는 유지하되 삭제된 파일의 다운로드 URL이나 저장 경로를 제공하지 않는다.
- 이전 분석 결과에 포함된 추출 정보와 인용 근거는 결과 기록의 일부로 유지한다. 여기에는 경력, 프로젝트명, 기술 스택과 원본 문장 일부가 포함될 수 있다.
- 보존된 추출 정보와 인용 근거는 원본 파일과 분리해 결과 기록에 귀속하며, 사용자가 피드백 목록에서 해당 결과를 삭제할 때 함께 즉시 영구 삭제한다.
- 삭제된 원본의 추출 정보는 새 면접 구성이나 새 분석의 입력으로 재사용하지 않는다.
- 사용자가 현재 원본 자료를 직접 삭제해도 이미 완료된 분석 결과와 피드백 기록은 유지한다.
- 삭제된 현재 자료를 기반으로 생성했지만 아직 시작하지 않은 면접 구성과 예상 질문은 즉시 무효화하고 새 면접 시작에 사용하지 않는다.
- 필수 이력서를 삭제한 뒤 새 면접을 시작하려면 이력서를 다시 업로드하고 최신 자료로 새 분석과 질문 생성을 완료해야 한다.
- 원본 파일 삭제와 새 파일 저장이 실패하면 교체 완료로 표시하지 않고 서버에서 확정된 현재 자료 상태를 다시 조회한다.

### 8.3 점수 실패

- 평가 점수는 `높임법`, `예의와 배려`, `상황 적합성`, `자연스러움` 네 항목으로 저장한다.
- 각 항목은 0~25점 범위의 정수만 허용하며 소수점은 사용하지 않는다.
- 종합 점수는 네 항목 점수의 합계로 계산하고 0~100점 범위의 정수로 저장한다.
- 항목별 점수 해석은 20~25점 `훌륭해요`, 15~19점 `잘했어요`, 10~14점 `나쁘지 않아요`, 0~9점 `조금 더 연습해요`로 표시한다.
- 종합 점수 해석은 80~100점 `훌륭해요`, 60~79점 `잘했어요`, 40~59점 `나쁘지 않아요`, 0~39점 `조금 더 연습해요`로 표시한다.
- 점수 구간의 양 끝값은 포함하며 모든 정수 점수는 정확히 하나의 해석에만 속한다.
- 네 항목 중 하나라도 점수 산정에 실패하면 합계를 종합 점수로 확정하지 않는다.
- 점수 산정에 실패하면 0점이나 임의 점수를 표시하지 않는다.
- 가능한 설명형 피드백과 성공한 분석만 제공한다.
- 결과 생성 전체가 실패해도 완료된 대화와 사용자 답변을 보존하고 재시도를 제공한다.
- 시도별 결과 기록은 대화방과 독립적으로 보존하며, 피드백 목록에서 사용자가 직접 삭제하기 전에는 재도전이나 대화방 삭제로 제거하지 않는다.
- 피드백 목록에서 삭제한 결과 기록과 종합 분석은 복구 기간 없이 즉시 영구 삭제한다.
- 결과 기록 삭제는 대화방, 메시지, 발화별 피드백과 TTS 음성에 영향을 주지 않는다.
- 결과 삭제 실패 시 목록에서 먼저 제거하지 않고 재시도를 제공한다.

- 대화방이 없으면 첫 연습 시작 행동을 제공한다.
- `in_progress` 대화방에는 `진행 중` 상태와 `이어하기`를 표시한다.
- `completed` 대화방에는 `종료됨` 상태와 `기록 보기`를 표시한다.
- 기술적인 종료 사유 값은 그대로 노출하지 않고 사용자 언어로 표시한다.
- 진행 중 대화방을 선택하면 입력 가능한 기존 대화 화면으로 이동한다.
- 종료된 대화방을 선택하면 해당 대화·결과를 읽기 전용으로 표시한다. Figma 1.2.0에는 별도 `C10` 프레임이 없으므로 구현 내부 상태로 처리한다.
- 진행 중인 면접에는 `이어하기`를 표시하며 종료 행동은 제공하지 않는다.
- 완료된 면접에는 `답변 보기` 또는 `결과 보기`를 표시한다.
- 같은 페르소나의 진행 중인 자유채팅방이 있으면 새 방을 만들지 않고 기존 방으로 이동한다.
- 종료된 자유채팅방이 있더라도 새 자유채팅을 시작할 수 있다.
- 종료된 방은 사용자가 직접 삭제하기 전까지 목록과 기록 조회에서 유지한다.
- 목록 조회 실패 시 이미 표시된 목록과 현재 입력을 보존하고 재시도를 제공한다.
- 다른 사용자의 방은 조회·이어하기·삭제할 수 없으며 소유 여부를 노출하지 않는 오류로 처리한다.
- 삭제 실패 시 목록에서 먼저 제거하지 않는다.
- 대화방 삭제는 해당 방의 메시지, 발화별 피드백과 생성된 TTS 음성을 하나의 삭제 단위로 처리한다.
- 삭제 확인 후 별도의 보관·복구 기간 없이 즉시 영구 삭제한다.
- 연결 데이터 중 하나라도 삭제하지 못하면 성공으로 표시하지 않고 서버의 확정된 결과를 다시 조회한다.

## 11. 화면 구현 의존 상태 요약

이 절은 화면 분기와 사용자 피드백에 필요한 상태만 요약한다. 저장 구조와 처리 순서는 정의하지 않으며 세부 계약은 API·ERD·아키텍처 문서를 따른다.

| 영역 | 필수 상태·데이터 |
| --- | --- |
| 인증 | 로그인 상태, 약관 동의, 필수 프로필 필드의 저장 상태, 필수 UI 언어 |
| 연습 선택 | 연습 유형, 페르소나, 선택 시나리오, 관계·목표 |
| 대화 | 대화 유형, 메시지 순서, 입력 출처, AI 응답 상태, 턴 수, `in_progress`·`completed`, 종료 사유, 읽기 전용 여부 |
| 음성 | 권한, 녹음, 변환, 전사 확인 여부, TTS의 `processing`·`succeeded`·`failed` 상태 |
| 감정 | 여섯 허용 상태, 분석 상태, 이미지 로딩 실패 시 `neutral` 대체 |
| 피드백 | 네 평가 항목과 종합 점수, 근거, 원문, 추천 표현, 생성·실패·재시도 상태 |
| 면접 자료 | 종류, 파일명, 형식, 크기, 업로드·분석 상태, 현재 사용 여부 |
| 결과 | 대화 유형, 종료 사유, 진행 시간, 완료 턴 수, 종합 피드백 상태, 누락 항목, 새 연습 진입점 |

- `goal_achieved_pending_choice`: 필수 성공 조건은 충족했지만 사용자가 종료 또는 계속하기를 선택하지 않은 UI 하위 상태. 대화방 상태는 `in_progress`다.
- `goal_achieved`: 목표 달성 카드에서 사용자가 `연습 종료`를 선택해 종료가 확정된 상태.
- `max_turns_reached`: 목표 미달성 상태에서 최대 턴 도달.
- `user_ended`: 자유채팅 또는 기본 상황 시나리오를 사용자가 종료.
- `interview_completed`: 모든 필수 답변과 면접관 종료 선언 이후 사용자가 최종 `면접 종료`를 확정.

## 12. 화면 완료 기준

- 지정한 화면의 진입·주요 행동·뒤로가기·하단 내비게이션이 Figma 1.2.0의 화면 배치와 상태 프레임에 연결된다.
- 텍스트와 음성 모두 전송 전에 사용자가 최종 내용을 통제할 수 있다. 녹음 종료는 전송 동의가 아니며, 잘못 인식된 문장이 그대로 상대에게 가지 않는다.
- 동일 발화 요청이 중복 도착해도 사용자 메시지·AI 응답·턴이 각각 한 번만 생성된다.
- 시나리오 턴은 사용자 답변과 AI 응답이 모두 확정된 경우에만 증가하고, 목표 달성·최대 턴 도달 또는 사용자 종료 시 `completed`로 종료된다.
- 시나리오는 유효한 `max_turns`와 하나 이상의 필수 성공 조건이 있어야 생성·시작할 수 있고, 모든 필수 조건 충족 시에만 목표 달성으로 판정된다.
- 자유채팅과 기본 상황 시나리오는 사용자가 종료할 수 있고, 종료 시 `completed`와 `user_ended`로 기록된다.
- 목표 달성은 사용자가 목표 달성 카드에서 종료를 선택한 뒤에만 `completed`가 되며, 최대 턴 도달·면접 완료·사용자 종료와 함께 종료 사유로 구분된다.
- 화면 나가기, 연습 종료와 대화방 삭제가 서로 다른 결과로 처리된다.
- 사용자 종료가 확정되면 종합 피드백이 한 번만 생성된다.
- 종료된 대화방은 대화방 목록에서 읽기 전용으로 다시 확인할 수 있다.
- 읽기 전용 화면에서는 입력·녹음·메시지 전송·AI 처리 재시도가 차단된다.
- 면접 화면에서도 사용자 중간 종료가 제공되며, 종료하지 않고 화면만 나가면 다시 이어갈 수 있다.
- 네 평가 항목과 여섯 감정 상태의 명칭이 전 화면에서 일치한다.
- 네 평가 항목은 각각 0~25 정수이고 종합 점수는 네 항목 합계인 0~100 정수로 일관되게 계산된다.
- 항목별·종합 점수의 모든 정수값이 중복이나 누락 없이 하나의 확정된 해석 문구에 매핑된다.
- 이력서 필수 조건과 자료별 형식·용량이 업로드 전후에 동일하게 표시된다.
- 한국어·영어 병기와 선택 언어 적용이 인증·온보딩에서 동작한다.
- 인증·온보딩의 병기 문구는 버튼 1줄, 제목·설명 2줄을 기본 상한으로 하며 의미를 훼손하지 않는 범위에서 자연 줄바꿈한다. 번역 문자열은 한국어 기준 폭의 150%까지 확장을 허용하고 넘으면 축소하지 않고 높이를 늘린다.
- 이름·나이·성별·모국어·UI 언어가 모두 유효하지 않으면 온보딩을 완료할 수 없다.
- 인증되지 않은 사용자는 인증·온보딩 외 화면과 사용자 데이터 API에 접근할 수 없다.
- 세션 만료 시 미전송·미저장 입력과 선택 파일이 남지 않으며 보호 요청이 처리되지 않는다.
- 면접 결과에 합격·불합격 판정을 제공하지 않는다.
- 로딩·빈 상태·오류·부분 성공에서 입력과 성공한 결과가 보존된다.
- AI 텍스트·TTS·감정 분석·발화별 피드백의 처리 상태를 독립적으로 저장하고 일부 실패를 전체 대화 실패로 처리하지 않는다.

### 13.5 대화 진행·종료

| 구분 | 조건 | 화면과 처리 기준 |
| --- | --- | --- |
| 정상 | 사용자 답변과 AI 응답이 모두 확정됨 | 턴 수를 1 증가시키고 성공 조건을 평가한다. |
| 정상 | 기본 상황 시나리오의 모든 필수 성공 조건 충족 | `in_progress/goal_achieved_pending_choice`로 목표 달성 카드를 표시한다. `연습 종료` 선택 시에만 `completed/goal_achieved`로 기록하고 종합 피드백을 생성한다. |
| 경계 | 목표 달성 카드에서 `계속하기` 선택 | 대화방을 `in_progress`로 유지하고 입력을 다시 활성화하며 같은 목표 달성 카드는 반복 노출하지 않는다. |
| 경계 | 일부 성공 조건만 충족 | `in_progress`를 유지하고 다음 대화를 진행한다. |
| 정상 | 목표 미달성 상태로 `max_turns` 도달 | `completed`와 `max_turns_reached`로 기록하고 종합 피드백을 생성한다. |
| 정상 | 자유채팅 또는 기본 상황 시나리오에서 사용자 종료 확인 | `completed`와 `user_ended`로 기록하고 종합 피드백을 생성한다. |
| 정상 | 면접관 종료 선언 뒤 사용자가 최종 `면접 종료` 확정 | `completed`와 `interview_completed`로 기록하고 면접 종합 피드백을 생성한다. |
| 경계 | 사용자 종료 확인에서 취소 | 상태와 입력을 변경하지 않고 기존 대화로 돌아간다. |
| 경계 | 화면 나가기·브라우저 종료·로그아웃 | 종료로 처리하지 않고 `in_progress`를 유지한다. |
| 경계 | AI 처리 중 사용자 종료 | 추가 입력을 차단하고 종료 이후 늦게 도착한 결과를 대화에 반영하지 않는다. |
| 경계 | 동일 종료 요청 중복 | 상태 전환과 종합 결과 생성을 각각 한 번만 수행한다. |
| 경계 | 사용자 발화 없이 종료 | 임의 점수를 표시하지 않고 평가 자료 부족과 새 연습 행동을 제공한다. |
| 경계 | 면접 진행 화면 | 중간 종료는 `종료`를 눌러 확인한 때에만 확정하고, 화면 이탈은 종료로 보지 않고 이어가기를 유지한다. |
| 경계 | 시작·종료 발화가 없음 | 임의 문장을 생성하지 않고 입력 대기 또는 상태 안내를 표시한다. |
| 실패 | 종료된 방에 새 발화 요청 | 메시지와 턴을 변경하지 않고 이미 종료된 대화임을 안내한다. |
| 실패 | 종료 상태 저장 실패 | `in_progress`를 유지하고 종료 실패와 재시도를 표시한다. |
| 실패 | 종료 후 종합 피드백 생성 실패 | `completed`를 유지하고 동일 결과 기록에 대한 피드백 재시도를 제공한다. |

### 13.6 면접 자료·분석

| 구분 | 조건 | 화면과 처리 기준 |
| --- | --- | --- |
| 정상 | 필수 이력서와 유효한 선택 자료 업로드 | 최신 자료 버전으로 분석과 질문 생성을 시작한다. |
| 경계 | 포트폴리오 또는 자기소개서 없음 | 이력서만으로 진행하며 누락 오류로 처리하지 않는다. |
| 경계 | 자료 교체 | 이전 원본은 즉시 영구 삭제하고, 이전 분석 결과는 보존하며 새 버전으로 재분석한다. |
| 경계 | 현재 원본 삭제 | 완료 분석은 보존하지만 미시작 면접 구성은 무효화한다. 이력서 삭제 시 재업로드 전 새 면접을 시작할 수 없다. |
| 실패 | 필수 이력서 없음, 미지원 형식, 10MB 초과 | 분석 시작을 차단하고 파일 교체를 제공한다. |
| 실패 | 분석·질문 생성이 1분 안에 완료되지 않음 | 현재 원본은 유지하고 동일 분석 레코드 재시도를 제공한다. |
| 실패 | 동일 자료 분석 중복 요청 | 하나의 처리로 합치고 분석 기록을 중복 생성하지 않는다. |

### 13.7 결과·피드백 기록

| 구분 | 조건 | 화면과 처리 기준 |
| --- | --- | --- |
| 정상 | 네 항목 점수 산정 성공 | 항목별 0~25 정수와 합계 0~100 정수, 확정 해석 문구를 표시한다. |
| 경계 | 일부 항목 점수 실패 | 종합 점수를 확정하지 않고 성공한 설명형 피드백만 표시한다. |
| 경계 | 대화방 삭제 또는 시나리오 재도전 | 시도별 결과 기록은 피드백 목록에 보존한다. |
| 정상 | 피드백 목록에서 결과 삭제 확인 | 해당 결과·종합 분석·보존된 추출 근거만 즉시 영구 삭제한다. |
| 실패 | 결과 삭제 실패 | 목록에서 제거하지 않고 재시도를 제공한다. |

### 13.8 대화방·회원 데이터 삭제

| 구분 | 조건 | 화면과 처리 기준 |
| --- | --- | --- |
| 정상 | 대화방 삭제 확인 | 방·메시지·발화별 피드백·TTS 음성·비공개 맥락 요약을 즉시 영구 삭제한다. 독립 결과 기록은 유지한다. |
| 정상 | 종료된 대화방 선택 | 전체 메시지와 기존 피드백을 읽기 전용으로 표시한다. |
| 정상 | 회원 탈퇴 최종 확인 | 프로필, 모든 대화 데이터, 원본 자료, 분석 결과, 면접 시나리오를 즉시 영구 삭제한다. |
| 경계 | 읽기 전용 화면에서 입력 시도 | 입력·녹음·전송 동작을 제공하지 않으며 새 메시지를 생성하지 않는다. |
| 경계 | 연습 종료 | 대화방과 연결 데이터를 삭제하지 않고 종합 피드백을 생성한다. |
| 경계 | 삭제 취소 | 어떤 데이터도 변경하지 않고 이전 화면으로 돌아간다. |
| 실패 | 일부 또는 전체 삭제 실패 | 삭제 성공으로 표시하지 않고 서버의 확정 상태를 다시 조회하며 재시도를 제공한다. |
