## 1. 한 줄 서비스 정의

K-Manner Speech는 외국인 한국어 학습자가 AI 페르소나와 텍스트 또는 음성으로 대화하며, 상대와의 관계·상황·목적에 맞는 한국어 표현과 매너를 연습하는 AI 회화 학습 서비스다.

## 2. 문제와 목표

문법적으로 맞는 문장도 관계와 상황에 따라 무례하거나 부자연스럽게 들릴 수 있다. 학습자는 실제 대화 전에 이를 안전하게 연습하고, 자신의 표현이 상대에게 줄 수 있는 인상과 더 적절한 대안을 구체적으로 확인할 수 있어야 한다.

MVP의 목표는 다음과 같다.

- 관계·상황·목적이 유지되는 AI 대화를 제공한다.
- 사용자의 표현을 높임법·예의와 배려·상황 적합성·자연스러움 관점에서 코칭한다.
- 감정·인상 분석을 사실이 아닌 AI의 추정으로 명확히 전달한다.
- 음성 기능 일부가 실패해도 가능한 텍스트 학습 흐름은 유지한다.
- 이력서·개인 자료를 사용한 면접 연습에서 목적 고지, 확인, 수정, 삭제 권리를 보장한다.

## 3. 대상 사용자

### 3.1 핵심 사용자

- 문법 지식은 있지만 관계와 상황에 맞는 표현을 연습하려는 외국인 한국어 학습자
- 한국 생활, 학교, 직장 또는 면접에서 높임말·예의·자연스러운 표현이 필요한 학습자
- 텍스트와 음성 중 자신에게 편한 방식으로 반복 연습하려는 학습자

### 3.2 핵심 사용자 과업

1. 학습 목적과 입력 방식을 정한다.
2. 자유 채팅, 기본 상황 또는 면접 시나리오를 선택한다.
3. 관계·상황·목표를 확인하고 대화한다.
4. 발화별 피드백과 감정·인상 추정을 확인한다.
5. 연습을 정상적으로 완료하거나 필요한 시점에 직접 종료한다.
6. 종료 시점까지의 대화를 기준으로 생성된 종합 피드백을 확인한다.
7. 추천 표현으로 다시 말하거나 같은 상황에 재도전한다.

## 5. 공통 제품 원칙

- 평가는 비난이 아닌 코칭으로 표현하며, 문제를 제시할 때 이유와 대안 표현을 함께 제공한다.
- 감정 분석은 `AI가 추정한 감정`, `이렇게 들릴 수 있어요`처럼 추정임을 표시한다.
- 성격, 정신 건강, 진실 여부 등 민감한 속성을 추론하지 않는다.
- 기술명보다 사용자의 행동과 결과를 설명한다.
- 핵심 비즈니스 판단, 인증·권한과 사용자 소유 데이터 접근은 서버에서 수행한다.
- 비밀값과 개인정보를 사용자 오류, 로그, 문서에 노출하지 않는다.
- 복합 AI 처리에서는 부분 성공을 허용하며 한 기능의 실패를 전체 대화 실패로 취급하지 않는다.
- 모든 핵심 기능은 정상·경계·실패 완료 기준을 충족해야 한다.
- 화면을 나가는 행동, 연습을 종료하는 행동과 대화방을 삭제하는 행동을 서로 구분한다.
- 연습 종료 원인에 따라 사용자의 학습 결과를 성공 또는 실패로 단정하지 않는다.
- 종합 피드백은 실제로 저장되고 평가할 수 있는 사용자 발화만을 근거로 생성한다.
- 사용자가 수행하지 않은 턴, 답변하지 않은 질문과 확인되지 않은 성공 조건에 임의의 점수나 평가를 부여하지 않는다.

## 6. 기능별 요구사항과 완료 기준

### FR-01. 온보딩

**요구사항**  
사용자는 시작 화면에서 로그인 또는 회원가입으로 진입한다. 회원가입은 계정 정보와 필수 약관 동의, 이름·생년월일·성별·모국어 프로필 입력, 한국어·영어 UI 언어 선택 순서로 진행한다. 이력서와 면접 자료는 온보딩에서 요구하지 않는다.

**완료 기준**

- 정상: 유효한 계정 정보와 필수 약관 동의 후 프로필을 저장하고 한국어 또는 영어를 선택하면 홈으로 이동한다. 선택한 UI 언어는 모든 메뉴와 안내에 적용되며 내 정보에서 다시 변경할 수 있다.
- 경계: 이미 계정이 있는 사용자는 로그인으로 돌아갈 수 있다. 선택하지 않은 UI 언어로는 다음 단계에 진행하지 않으며, 각 프로필 항목의 필수 여부와 허용 형식을 표시한다.
- 실패: 계정 또는 프로필 저장이 실패해도 입력값을 보존하고 재시도할 수 있다. 빈 이름, 유효하지 않은 생년월일 또는 서버가 허용하지 않는 열거값은 저장하지 않고 해당 항목과 허용 조건을 구체적으로 안내한다.

### FR-02. 연습 유형 선택과 준비

**요구사항**  
사용자는 자유 채팅, 기본 상황 시나리오 1개, 이력서 기반 면접 시나리오 1개 중 하나를 선택한다. 시작 전에 관계, 상황, 목표, 성공 조건, 예상 시간, 입력 방식과 개인 자료 사용 여부를 확인한다.

**완료 기준**

- 정상: 세 유형이 서로 구분되고, 선택한 유형의 관계·상황·목표를 확인한 뒤 연습을 시작할 수 있다. 진행 중인 연습에는 `이어하기`가 제공된다.
- 경계: 로그인이 필요한 연습은 핵심 관계와 학습 목적을 읽을 수 있으며, 잠금 이유와 로그인이라는 다음 행동을 함께 안내한다.
- 실패: 시나리오 정보를 불러오지 못하면 빈 카드나 무반응 상태 대신 실패 원인 범주와 재시도를 제공하고, 사용할 수 있는 다른 연습 유형은 유지한다.

### FR-03. 대화 맥락 유지

**요구사항**  
AI는 선택된 관계, 상황, 대화 목적과 같은 대화방의 전체 대화 맥락에 맞게 응답한다. 입력 한도를 넘으면 오래된 메시지부터 요약하고 최근 메시지는 원문으로 유지한다. 요약은 대화방 내부 데이터로 저장·갱신하되 사용자에게 표시하지 않는다.

**완료 기준**

- 정상: 같은 대화 세션 안에서 AI 응답과 피드백이 준비 단계에서 확인한 관계·상황·목적을 기준으로 생성된다.
- 경계: 자유 채팅처럼 관계나 목적이 명시되지 않은 경우, 설정되지 않은 맥락을 임의의 사실로 단정하지 않는다.
- 실패: 필수 맥락을 불러오지 못하면 잘못된 관계로 대화를 진행하지 않고, 사용자가 맥락을 다시 확인하거나 연습을 재시작하도록 안내한다.

### FR-04. 텍스트 대화

**요구사항**  
사용자는 텍스트를 전송하고 AI의 텍스트 응답을 읽으며 연속 대화할 수 있다.

**완료 기준**

- 정상: 유효한 텍스트를 전송하면 전송 중, 전송 완료, 응답 생성 중, 응답 완료 상태가 구분되고 AI 텍스트 응답이 대화에 추가된다. 동일 발화 요청은 멱등 처리해 사용자 메시지와 AI 응답을 한 번만 생성한다.
- 경계: 빈 값 또는 공백만 있는 입력은 전송하지 않는다. 여러 줄 입력을 허용하고 입력 내용이 5줄을 넘으면 입력 영역 내부에서 확인할 수 있다.
- 실패: AI 텍스트 응답이 15초 안에 완료되지 않거나 실패하면 사용자 메시지를 유지하고 같은 단일 응답 레코드의 재시도를 제공한다. 내부 오류나 민감한 정보를 노출하지 않는다.

### FR-05. 음성 입력(STT)

**요구사항**  
사용자는 음성을 텍스트로 변환하고 결과를 확인·수정한 뒤 전송할 수 있다.

**완료 기준**

- 정상: 마이크 권한이 있는 지원 환경에서 녹음 시작, 듣는 중, 변환 중, 확인 상태가 구분되며 변환 텍스트를 수정하고 전송할 수 있다. 전송 메시지에는 음성 입력임이 표시된다.
- 경계: 음성 입력은 어떤 경우에도 자동 전송하지 않는다. 인식 결과는 입력창에 채워지고 사용자가 확인·수정한 뒤 직접 보낸다. 결과가 없거나 신뢰하기 어려우면 재녹음 또는 텍스트 입력을 선택할 수 있다.
- 실패: 권한 거부 또는 Web Speech API 미지원 시 이유와 텍스트 입력 대체 경로를 즉시 제공한다. 실패한 음성을 성공한 것처럼 표시하지 않는다.

### FR-06. 음성 출력(TTS)

**요구사항**  
AI 응답 텍스트는 음성 준비 여부와 관계없이 먼저 읽을 수 있어야 하며, 텍스트가 표시된 직후 TTS 자동 재생을 시도한다. 사용자는 재생을 제어하고 다시 들을 수 있다.

**완료 기준**

- 정상: 음성 자동 재생을 켠 환경에서는 AI 응답 텍스트를 표시한 직후 TTS 자동 재생을 시도한다. 재생·일시정지·처음부터 다시 듣기와 현재 재생 상태를 제공한다.
- 경계: TTS가 아직 준비되지 않았으면 AI 텍스트를 먼저 표시하고 `음성 만드는 중` 상태를 알린다. 자동 재생이 차단되면 `눌러서 답변 듣기`를 표시한다. 사용자가 자동 재생을 끄거나 음소거하면 이후 응답에도 그 선택을 유지하며, 동시에 두 메시지를 재생하지 않는다.
- 실패: AI 텍스트 표시 후 TTS가 45초 안에 준비되지 않거나 생성·재생에 실패해도 이미 표시한 AI 텍스트와 가능한 피드백을 유지한다. 음성 재시도를 제공하고 음성이 재생된 것처럼 표시하지 않는다. 재생성 성공 시 메시지당 최종 음성 하나만 연결하고 이전 파일은 즉시 영구 삭제한다.

### FR-07. 표현 평가와 코칭

**요구사항**  
각 사용자 발화에는 높임법, 예의와 배려, 상황 적합성, 자연스러움의 네 항목 평가와 실행 가능한 대안이 제공된다. 각 항목은 0~25 정수이고 종합 점수는 네 항목 합계인 0~100 정수다.

**완료 기준**

- 정상: 네 항목의 항목명과 점수, 종합 점수, 한 줄 요약, 잘한 점, 개선할 점, 원래 표현, 추천 표현, 관계·맥락상 추천 이유, `추천 표현으로 다시 말하기`가 제공된다. 항목별 해석은 20~25 `훌륭해요`, 15~19 `잘했어요`, 10~14 `나쁘지 않아요`, 0~9 `조금 더 연습해요`이며 종합 해석은 80~100, 60~79, 40~59, 0~39에 같은 순서로 적용한다.
- 경계: 개선할 내용이 적더라도 잘한 점과 맥락 설명을 유지한다. 점수는 숫자만 또는 색상만으로 전달하지 않고 해석을 함께 제공한다.
- 실패: 발화 전송 후 피드백이 30초 안에 준비되지 않거나 점수 산정에 실패하면 임의 점수를 만들지 않는다. 생성 가능한 설명형 피드백만 제공하며, 피드백 전체가 실패하면 대화는 유지하고 기존 단일 피드백 레코드의 재시도를 제공한다.

### FR-08. 감정·인상 분석

**요구사항**  
사용자의 텍스트 또는 음성에서 추정한 감정과 상대가 받을 수 있는 인상을 학습 정보로 제공한다.

**완료 기준**

- 정상: `AI가 추정한 감정과 인상`임을 명시하고 주요 감정을 최대 3개까지 비율과 함께 제공한다. 음성 분석은 톤·속도·강세 등의 관찰 근거를, 텍스트 분석은 텍스트 근거만 사용한다.
- 경계: 결과가 불확실하거나 사용자가 다르게 느끼는 경우 단정하지 않고 추정 결과의 한계를 안내한다.
- 실패: 발화 전송 후 감정 분석이 15초 안에 준비되지 않거나 실패하면 감정값을 임의 생성하지 않고 `neutral` 표시 원칙을 적용한다. 대화와 표현 피드백은 가능한 범위에서 유지한다.

### FR-09. 페르소나 감정 반응

**요구사항**  
동일한 AI 페르소나는 분석 결과에 따라 사전 검수된 여섯 감정 이미지를 사용한다.

**완료 기준**

- 정상: 시작 전에는 `neutral`을 표시하고 AI 응답의 감정이 확정되면 `neutral`, `happy`, `sad`, `angry`, `curious`, `embarrassment` 중 하나로 전환한다. 한 AI 메시지 중 표정은 한 번만 확정된다.
- 경계: 모호함, 허용되지 않은 값, 분석 중 또는 분석 실패는 `neutral`로 처리한다. 감정은 색상만이 아니라 표정과 텍스트 라벨로 구분한다.
- 실패: 해당 감정 이미지가 없거나 로드에 실패하면 `neutral`로 복귀한다. 기본 이미지도 실패하면 실루엣, 페르소나 이름과 감정 라벨을 제공한다.

### FR-10. 이력서 기반 면접 연습

**요구사항**  
사용자는 필수 이력서와 선택 자료를 제공해 자신의 정보에 근거한 면접 시나리오를 연습할 수 있다. 이력서와 자기소개서는 PDF 또는 DOCX 10MB 이하를 허용하고, 포트폴리오는 선택 PDF 10MB 이하를 허용한다.

**완료 기준**

- 정상: 업로드 전에 자료별 허용 형식, 최대 10MB, 이용 목적, 보관 기간과 삭제 방법을 확인할 수 있다. 필수 이력서 업로드와 분석이 완료되면 반영할 지원 조건과 자료를 최종 확인하고 면접 연습을 시작할 수 있다.
- 경계: 포트폴리오와 자기소개서는 생략할 수 있다. 추출 정보가 일부 누락되면 이를 표시하고 사용자가 자료를 교체하거나 다시 분석할 수 있게 한다.
- 실패: 미지원 형식, 크기 초과, 업로드 또는 처리 실패를 구분해 안내하고 재시도 또는 파일 교체를 제공한다. 실패한 자료로 면접 내용을 생성하지 않는다.
- 개인정보: 자료와 생성된 시나리오를 삭제할 수 있고, 다른 사용자의 시나리오에 쓰인다는 인상을 주지 않으며, 홈 미리보기에서 민감 내용을 노출하지 않는다.
- 생명주기: 현재 원본은 사용자가 삭제·교체하거나 회원 탈퇴할 때까지 보존한다. 교체·삭제한 원본은 즉시 영구 삭제하지만 기존 분석 결과와 그 안의 추출 정보·인용 근거는 피드백 목록에서 결과를 삭제할 때까지 보존한다. 새 자료 버전은 새 분석을 만들고 동일 버전의 실패 재시도는 기존 분석 레코드를 갱신한다.
- 시간 초과: 자료 분석과 예상 질문 생성이 1분 안에 완료되지 않으면 원본은 유지하고 분석만 실패 처리해 재시도한다.
- 면접 완료: 면접 구성은 1~10개의 필수 질문을 가진다. 마지막 답변에 대한 면접관의 종료 발화가 저장되면 방을 `in_progress`, `ended_reason = 'awaiting_user_end'`로 유지하고 `면접 종료` 버튼을 제공한다. 사용자가 이 버튼을 누르면 `completed`, `ended_reason = 'interview_completed'`로 확정하고 종합 피드백 생성을 시작한다.
- 면접 중간 종료: 질문이 남아 있어도 사용자는 면접을 끝낼 수 있다. `completed`, `ended_reason = 'user_ended'`로 확정하고, 면접 구성을 `completed`로 옮긴 뒤 그때까지의 답변으로 종합 피드백을 생성한다. 남은 질문을 이유로 종료를 막으면 결과를 볼 방법이 없는 방이 남는다.
- 시나리오 조기 목표 달성: 제한 턴 전에 필수 성공 조건이 모두 충족되면 방을 바로 끝내지 않고 `in_progress`, `ended_reason = 'goal_achieved'`로 두어 사용자에게 종료할지 이어갈지 묻는다. 이어가기를 고르면 같은 제안을 반복하지 않고 남은 턴까지 진행한다. 목표를 이루고도 턴을 채우기 위해 대화를 늘려야 하는 상황을 만들지 않는다.

### FR-11. 결과와 복습

**요구사항**  
목표 달성, 최대 턴 도달 또는 사용자 요청으로 연습이 종료되면 종료 시점까지 저장이 완료된 대화를 기준으로 종합 피드백을 생성한다. 종합 피드백에는 종료 사유, 실제 진행 시간, 완료된 턴 수, 평가 가능한 항목별 점수, 잘한 표현, 고쳐볼 표현 최대 3개와 목표 달성 여부를 제공한다. 사용자가 직접 종료한 자유채팅과 기본 상황 시나리오도 다른 종료 유형과 동일한 결과 화면과 종합 피드백 생성 절차를 사용한다.

**완료 기준**

- 정상: 목표 달성, 최대 턴 도달 또는 사용자 요청으로 대화방이 `completed`가 되면 해당 연습의 종합 피드백 생성을 시작한다. 결과에는 종료 사유, 실제 진행 시간, 완료된 턴 수, 종합 점수, 네 항목 점수, 잘한 표현, 고쳐볼 표현 최대 3개, 감정·인상 요약, 목표 달성 여부, 다시 말하기와 같은 상황 재도전을 제공한다.
- 정상: 사용자가 자유채팅 또는 기본 상황 시나리오를 중간에 종료한 경우에도 종료 시점까지 저장이 완료된 사용자 발화를 기준으로 종합 피드백을 생성하며, 중간 종료 여부 자체를 항목별 점수나 종합 점수의 감점 요소로 사용하지 않는다.
- 경계: 사용자 발화가 하나 이상 저장된 경우 해당 발화를 평가 대상으로 사용할 수 있다. AI 응답까지 확정된 턴과 사용자 발화만 저장된 미완료 턴은 결과에서 구분한다.
- 경계: 평가할 수 있는 사용자 발화가 없으면 점수와 표현 피드백을 임의로 생성하지 않고 `평가할 대화가 부족해요`라는 안내와 새 연습 시작 행동을 제공한다.
- 경계: 평가할 사용자 발화가 한 턴도 없는 방을 종료하면 방만 종료하고 종합 피드백은 생성하지 않는다. 근거 없는 결과를 만들지 않기 위해서다.
- 경계: 사용자가 중간 종료한 기본 상황 시나리오에서는 종료 시점까지 확인된 성공 조건만 목표 달성 판단에 사용한다. 확인되지 않은 성공 조건은 실패로 단정하지 않고 `연습 종료 전 확인되지 않음`으로 표시한다.
- 경계: 수행하지 않은 턴, 답변하지 않은 질문과 생성 중이던 AI 응답을 평가 근거로 사용하지 않는다. 일부 분석만 성공한 경우 성공한 결과를 먼저 제공하고 누락 항목을 명확히 표시하며 점수가 없는 항목을 0점으로 표시하지 않는다.
- 실패: 종합 피드백 생성이 실패해도 대화방의 `completed` 상태, 완료된 대화 기록과 사용자 입력을 유지한다. 기존 결과 기록을 대상으로 재시도하고 중복 결과 기록을 생성하지 않는다.

### FR-12. 접근성·반응형·상태 처리

**요구사항**  
MVP는 반응형 웹과 모바일 앱에서 같은 정보 구조를 제공하며 WCAG 2.2 AA를 목표로 한다.

**완료 기준**

- 정상: 모든 핵심 동작을 키보드로 수행할 수 있고 포커스가 보인다. 일반 텍스트 대비 4.5:1, 큰 텍스트·핵심 그래픽 3:1, 터치 대상 44×44px 이상, 텍스트 200% 확대 조건을 충족한다.
- 경계: 감정·점수·상태를 색상만으로 전달하지 않으며, 음성에는 동일한 텍스트, 이미지에는 역할과 감정을 설명하는 대체 텍스트를 제공한다. 동작 감소 설정에서는 반복 모션을 제거한다.
- 실패: 오프라인, 시간 초과, 부분 성공, 빈 상태와 오류 상태에는 현재 상태와 재시도 또는 대체 경로가 제공된다. 오류가 사용자의 탓이라고 단정하지 않는다.

### FR-13. 페르소나·시나리오 카탈로그

**요구사항**
사용자는 대화 상대와 연습 상황의 목록·상세 정보를 조회하고, 실제로 선택 가능한 페르소나–시나리오 조합만 골라 대화방을 만들 수 있다. 페르소나에는 이름·소개·관계가, 시나리오에는 제목·목표·난이도·예상 시간·장소·종료 조건·턴 상한이 필요한 시점에 제공된다.

**완료 기준**

- 정상: 페르소나 목록에서 상대를 선택하면 해당 상대의 상세 관계와 선택 가능한 시나리오만 표시된다. 반대로 시나리오 상세에서는 선택 가능한 페르소나가 표시되며, 표시된 조합으로 대화방을 만들 수 있다.
- 경계: 선택 가능한 시나리오 또는 페르소나가 0개이면 빈 카드 대신 `현재 선택할 수 있는 항목이 없어요`와 이전 선택으로 돌아가는 행동을 표시한다. 난이도·예상 시간·장소 같은 선택 정보가 없으면 임의 값을 만들지 않고 생략하거나 명시된 기본 표시 규칙을 적용한다.
- 실패: 존재하지 않는 식별자 또는 허용되지 않은 페르소나–시나리오 조합으로 대화방을 만들지 않는다. 목록·상세 조회 실패 시 실패한 영역과 재시도를 표시하고 이미 조회한 다른 카탈로그 정보는 유지한다.
- 기본 상황: `부서 팀장에게 마감 연장 요청하기`는 10턴이며 `정중한 요청`, `새 마감일 제시`, `팀장의 명시적 동의`를 모두 충족해야 완료된다.

### FR-14. 대화방과 대화 이력 관리

**요구사항**
사용자는 페르소나와 선택적 시나리오로 대화방을 만들고, 자신의 진행 중인 대화방 목록과 메시지·발화별 피드백 이력을 조회해 이어갈 수 있다. 사용자는 진행 중인 연습을 유형과 무관하게 종료하거나 더 이상 필요하지 않은 대화방을 삭제할 수 있다. 연습 종료는 대화와 결과를 보존하는 행동이며, 대화방 삭제는 대화와 연결 데이터를 영구 삭제하는 행동이다.

**완료 기준**

- 정상: 진행 중인 대화방에는 유형과 무관하게 `이어하기`와 `종료` 행동을 제공한다. 종료된 대화방에는 이어하기 대신 `대화 기록 보기`, `종합 피드백 확인`, `새 연습 시작` 행동을 제공한다.
- 정상: 사용자가 연습을 종료해도 저장된 메시지, 발화별 피드백, TTS 음성과 내부 맥락 요약을 보존한다. 대화방 삭제를 확인하면 방, 메시지, 발화별 피드백, TTS 음성과 내부 맥락 요약을 즉시 영구 삭제하며 독립된 시도별 종합 결과는 사용자가 피드백 목록에서 직접 삭제하기 전까지 보존한다.
- 경계: 화면을 나가거나 브라우저를 닫거나 로그아웃하는 행동은 연습 종료로 처리하지 않는다. 진행 중인 방을 다시 열면 저장된 메시지부터 이어간다.
- 경계: `연습 종료`와 `대화방 삭제`의 차이와 각 행동 이후 보존되는 데이터를 구분하여 안내한다. 종료된 방은 기존 대화를 읽기 전용으로 제공하고 새 메시지를 입력할 수 없게 한다.
- 경계: 메시지나 피드백이 없는 새 방은 빈 대화 안내와 첫 입력 행동을 제공한다. 같은 조합의 진행 중인 방은 새로 만들지 않고 기존 방으로 이동하며 종료된 방으로 재진입하지 않고 새 대화방을 생성한다.
- 실패: 종료 저장에 실패하면 방을 종료된 것처럼 표시하지 않고 마지막으로 확정된 상태와 종료 재시도를 제공한다. 삭제에 실패하면 방을 목록에서 제거된 것처럼 표시하지 않는다.
- 실패: 존재하지 않거나 다른 사용자가 소유한 방·메시지·음성은 동일한 찾을 수 없음 응답으로 처리해 소유 여부를 노출하지 않는다. 목록·이력 조회 실패 시 현재 화면의 입력과 이미 표시된 이력을 보존하며 재시도를 제공한다.

### FR-15. 대화 진행과 종료 상태

**요구사항**
사용자는 진행 중인 연습을 종류와 상관없이 직접 종료할 수 있다. 자유채팅, 기본 상황 시나리오와 이력서 기반 면접이 모두 해당한다. 화면을 나가는 행동과 연습 종료는 구분하며, 연습 종료는 사용자의 확인을 받은 후 서버에서 확정한다. 면접관이 종료를 선언한 뒤의 최종 완료는 이와 별개의 행동으로 남는다.

대화방 진행 상태는 `in_progress`, `completed`로 구분한다. 목표 달성, 최대 턴 도달, 면접 완료 또는 사용자 종료가 확정되면 대화방을 `completed`로 전환한다. 종료 원인은 `goal_achieved`, `max_turns_reached`, `interview_completed`, `user_ended`로 구분하여 기록한다. 종료 사유와 관계없이 종료된 대화에는 새로운 발화를 추가할 수 없으며 종료 시점까지 저장된 대화를 기준으로 종합 피드백을 생성한다.

**완료 기준**

- 정상: `start_message`가 있으면 첫 AI 메시지로 한 번만 표시하고 없으면 사용자가 먼저 발화한다. 사용자 답변과 AI 응답이 모두 확정되면 1턴으로 계산한다.
- 정상: 기본 상황 시나리오의 모든 필수 성공 조건을 충족하면 턴 상한 전이라도 `completed`로 전환하고 종료 사유를 `goal_achieved`로 기록한다. 목표를 달성하지 못한 채 정확히 `max_turns`에 도달하면 `completed`와 `max_turns_reached`로 기록한다.
- 정상: 모든 필수 질문에 대한 답변 이후 면접관의 종료 발화가 저장되면 `in_progress`와 `awaiting_user_end`를 유지하며 추가 답변을 차단하고 `면접 종료` 버튼을 제공한다. 사용자가 이 버튼을 누르면 `completed`와 `interview_completed`로 기록하고 종합 피드백 생성을 시작한다.
- 정상: 사용자가 자유채팅 또는 기본 상황 시나리오의 종료를 확정하면 `completed`와 `user_ended`로 기록하고 추가 입력·음성 녹음·AI 응답 재시도를 차단한 뒤 종합 피드백 생성을 시작한다.
- 경계: 사용자가 종료 확인 단계에서 취소하면 상태와 입력 내용을 변경하지 않고 기존 대화로 돌아간다. 화면 이동, 브라우저 종료 또는 로그아웃은 연습 종료로 처리하지 않는다.
- 경계: 이력서 기반 면접에는 면접 도중의 `연습 종료` 행동을 제공하지 않는다. 면접관 종료 선언 전 화면을 나가면 `in_progress`를 유지하고 다음 미답변 질문부터 이어가며, 종료 선언 후 다시 진입하면 최종 `면접 종료` 버튼을 다시 제공한다.
- 경계: 사용자 종료 시 처리 중인 미완료 턴은 완료된 턴으로 계산하지 않는다. 종료 요청 당시 저장이 완료된 마지막 사용자 발화는 표현 평가에 사용할 수 있지만 생성 중이던 AI 응답은 종합 피드백의 근거로 사용하지 않는다.
- 경계: 종료 요청 후 처리 중인 AI 응답·TTS·감정 분석·발화별 피드백이 종료된 대화에 새로 반영되지 않게 한다. 동일한 종료 요청이 중복되어도 상태 전환과 종합 피드백 생성은 각각 한 번만 수행한다.
- 경계: `max_turns` 또는 필수 성공 조건이 없는 기본 상황 시나리오는 생성·시작하지 않는다. 준비된 종료 발화가 없으면 임의 문장을 만들지 않고 종료 상태와 결과·재도전 행동만 제공한다.
- 실패: 종료 상태 저장에 실패하면 완료된 것으로 표시하지 않고 마지막으로 확정된 `in_progress` 상태와 종료 재시도를 제공한다.
- 실패: 대화 종료는 성공했지만 종합 피드백 생성에 실패한 경우 `completed` 상태를 되돌리지 않고 동일한 결과 기록에 대한 재시도를 제공한다.
- 실패: `completed` 상태의 방에 새 발화를 보내면 메시지와 턴 수를 변경하지 않고 이미 종료된 대화임을 안내한다.

### FR-16. 생성 음성 보관과 조회

**요구사항**
TTS 생성에 성공한 AI 메시지는 해당 메시지의 생성 음성과 연결된다. 사용자는 자신의 대화방 안에서 메시지별 음성을 다시 들을 수 있으며, 음성 조회에도 대화방과 동일한 소유권 검사를 적용한다.

**완료 기준**

- 정상: TTS 생성에 성공한 AI 메시지에서 `다시 듣기`를 선택하면 그 메시지에 연결된 음성이 재생되고 다른 메시지의 음성과 바뀌지 않는다. 화면을 다시 열어도 저장된 메시지에 음성이 연결되어 있으면 다시 들을 수 있다.
- 경계: 텍스트 메시지, TTS가 생성되지 않은 메시지 또는 음성 경로가 없는 메시지에는 재생 완료 상태를 표시하지 않고 `음성을 사용할 수 없어요`와 가능한 재생성 행동을 제공한다. 한 메시지의 재생을 시작하면 이미 재생 중인 다른 메시지는 중지한다.
- 실패: 존재하지 않는 파일명, 허용되지 않은 확장자, 경로 조작 형태의 요청 또는 다른 사용자의 음성 요청은 음성을 반환하지 않는다. 저장소 다운로드 실패 시 메시지 텍스트를 유지하고 다시 듣기 실패와 재시도를 표시하며 내부 저장 경로를 노출하지 않는다.

### 인증·보존 확정 정책

- 비로그인 사용자는 인증·온보딩 화면만 접근하며 홈 이후 화면과 사용자 데이터 API는 모두 인증이 필요하다.
- 세션 만료 시 미저장 입력은 임시 보존하지 않고 로그인으로 이동하며 재로그인 성공 후 홈으로 이동한다.
- 연습 종료와 대화방 삭제는 서로 다른 행동이다.
- 사용자가 자유채팅 또는 기본 상황 시나리오를 종료해도 저장이 완료된 메시지, 발화별 피드백, TTS 음성과 종합 결과를 보존한다.
- 사용자가 종료한 연습에는 새로운 메시지를 추가할 수 없으며 새로운 연습은 별도의 대화방으로 생성한다.
- 종합 피드백 생성에 실패해도 종료된 대화방을 다시 `in_progress`로 변경하지 않는다.
- 회원 탈퇴 시 프로필, 모든 대화 데이터, 원본 자료, 분석 결과와 생성 면접 시나리오를 즉시 영구 삭제한다.

## 7. 핵심 사용자 흐름

### 7.1 일반 회화

온보딩 또는 기존 설정 확인 → 자유 채팅/기본 상황 선택 → 페르소나와 허용된 시나리오 조합 확인 → 관계·상황·목표 확인 → 대화방 생성 또는 이어하기 → 텍스트 또는 음성 발화 → AI 응답 텍스트 표시 직후 TTS 재생 시도 → 발화별 피드백·감정 추정 확인 → 목표 달성·최대 턴 도달 또는 사용자 종료 → 종합 피드백 생성 → 결과 확인 → 다시 말하기·재도전 또는 새 연습 시작

### 7.2 이력서 기반 면접

면접 연습 선택 → 자료 이용 목적·정책 확인 → 파일 업로드 → 처리 상태 확인 → 지원 조건·반영 자료 최종 확인 → 면접 맥락 확인 → 대화 → 발화별 코칭 → 결과 확인 → 자료 또는 생성 시나리오 삭제

## 8. 비기능 제품 요구사항

- 보안·권한: 인증과 사용자 소유 데이터 접근은 서버에서 검증하며 요청에 포함된 사용자 식별자를 그대로 신뢰하지 않는다.
- 개인정보: 필요 최소한만 수집하고 목적, 보관 기간, 삭제 방법을 고지한다. 비밀값과 개인정보를 오류나 로그에 노출하지 않는다.
- 복원력: 외부 AI, 음성 또는 이미지 기능 실패 시 성공한 결과와 사용자 입력을 보존한다.
- 일관성: 동일 개념에는 동일 용어를 사용하고 페르소나 이미지 감정 상태는 `neutral`, `happy`, `sad`, `angry`, `curious`, `embarrassment`의 여섯 값으로 정규화한다.
- 검증성: 각 요구사항은 외부에서 관찰 가능한 정상·경계·실패 기준으로 검수한다.

## 9. 이번에 만들지 않을 것

- 시나리오·페르소나 유사도 검색 및 검색 UI
- 대화 중 실시간 페르소나 이미지 생성
- `neutral`, `happy`, `sad`, `angry`, `curious`, `embarrassment` 외의 세분화된 페르소나 감정 이미지
- 실제 인물·유명인 모사 또는 권리·동의가 불명확한 참조 이미지 사용
- 성격, 정신 건강, 진실 여부 등 민감 속성 추론
- 문서 근거 없이 추가하는 결제·구독 또는 무료/프리미엄 구분
- 문서 근거 없이 추가하는 소셜 기능, 랭킹, 게임화, 다수의 신규 시나리오
- 구현 기술 변경, API 계약, 화면 상세 설계, 데이터베이스 설계

## 10. 확정된 세부 정책

인증 범위, 기본 상황 시나리오, 자료·대화·결과 보존과 삭제, 전체 대화 맥락 요약, 점수 계산·해석, AI 처리 시간 초과와 대화 상태 정책은 본 문서의 기능별 요구사항과 완료 기준으로 확정했다. 새로운 미결정 사항이 발견되면 가정으로 구현 범위를 넓히지 않고 제품 책임자 확인 후 이 문서를 갱신한다.

## 11. 출시 판정 기준

v1.1.0 출시는 다음을 모두 만족할 때 승인한다.

- FR-01~FR-16의 정상·경계·실패 기준이 검수되고 미충족 항목이 공개되어 있다.
- 자유 채팅, 기본 상황 1개, 이력서 기반 면접 1개의 시작부터 결과·재도전까지 핵심 흐름이 연결된다.
- 자유채팅과 기본 상황 시나리오에서 화면 나가기, 사용자 종료와 대화방 삭제가 서로 구분되어 동작한다.
- 사용자가 종료한 자유채팅과 기본 상황 시나리오는 `completed`와 `user_ended`로 기록되고 종료 시점까지의 종합 피드백이 한 번만 생성된다.
- 이력서 기반 면접에도 사용자 중간 종료 행동이 노출되고, 종료하지 않고 화면만 나가면 다음 미답변 질문부터 이어갈 수 있다.
- AI·STT·TTS·감정 분석·이미지 중 하나가 실패해도 가능한 텍스트 학습 결과와 입력이 보존된다.
- 음성 자동 재생이 켜진 정상 환경에서 AI 응답 텍스트가 먼저 표시되고 그 직후 TTS 자동 재생이 시도된다.
- 개인정보의 수집 목적, 보관 기간, 삭제 방법이 확정·고지되고 사용자 소유 데이터 접근이 보호된다.
- 접근성 목표와 핵심 예외 상태가 검수된다.
- 범위 밖 기능이 MVP에 포함되지 않는다.
