# K-Manner Speech 디자인 시스템

> 상태: MVP 1.0 하이브리드 기준안  
> 대상: 반응형 웹과 모바일 앱  
> 문서 목적: 기획·디자인·프론트엔드·AI 응답 UI가 같은 언어와 규칙을 사용하도록 한다.

## 1. 제품 정의

K-Manner Speech는 외국인 한국어 학습자가 문법적으로 맞는 문장을 만드는 데서 더 나아가, 상대방과의 관계와 대화 상황에 맞는 표현을 연습하도록 돕는 AI 회화 학습 서비스다.

이 문서가 정의하는 경험의 중심은 다음과 같다.

- 사용자는 텍스트나 음성으로 AI 페르소나와 대화한다.
- AI는 관계, 상황, 대화 목적과 최근 맥락을 유지한다.
- AI 응답은 텍스트와 TTS 음성으로 함께 제공한다.
- 사용자의 표현을 항목별로 점수화하고 구체적인 대안 표현을 제시한다.
- 음성 또는 텍스트에서 추론한 감정과 상대가 받을 수 있는 인상을 학습 정보로 제공한다.
- 페르소나는 `화남`, `기쁨`, `슬픔`의 세 가지 감정 상태를 시각적으로 표현한다.
- 사용자의 이력서와 개인 데이터를 활용해 RAG 기반 면접 시나리오를 제공한다.

## 2. 디자인 원칙

### 2.1 대화가 주인공이다

대화 화면에서는 페르소나, 채팅 메시지, 입력 컨트롤이 가장 높은 우선순위를 갖는다. 점수, 분석, 설정은 대화를 방해하지 않으며 사용자가 원할 때 자세히 펼쳐본다.

### 2.2 평가는 비난이 아닌 코칭이다

점수는 사용자를 심판하는 수치가 아니라 개선 방향을 찾는 신호다. 오류보다 먼저 잘한 점을 알려주고, 문제 표현에는 반드시 이유와 대안 표현을 함께 제공한다.

### 2.3 감정은 사실이 아닌 추정으로 표현한다

텍스트와 음성 기반 감정 분석은 확정적인 심리 판정이 아니다. UI에는 항상 `AI가 추정한 감정` 또는 `이렇게 들릴 수 있어요`와 같은 표현을 사용한다.

### 2.4 문화적 맥락을 명확하게 보여준다

피드백에는 `누구에게`, `어떤 상황에서`, `왜 이 표현이 적절한지`가 드러나야 한다. 단순히 “자연스럽지 않음”으로 끝내지 않는다.

### 2.5 학습 흐름은 점진적으로 공개한다

기본 화면에는 다음 행동에 필요한 정보만 노출한다. 상세 점수, 감정 비율, 문장별 설명은 확장 패널이나 상세 화면에서 제공한다.

### 2.6 언어 장벽을 낮춘다

짧은 문장, 쉬운 용어, 일관된 아이콘과 보조 설명을 사용한다. 아이콘만으로 의미를 전달하지 않으며 핵심 컨트롤에는 텍스트 라벨을 함께 제공한다.

### 2.7 감성은 유지하고 행동은 명확하게 한다

기존 화면 기획의 따뜻한 아이보리 배경, 실사형 페르소나, 코발트 블루 포인트와 부드러운 카드 표현을 유지한다. 동시에 전송·재생·녹음·이어하기처럼 의미가 다른 행동에는 아이콘과 텍스트 라벨을 함께 사용해 모호함을 없앤다.

### 2.8 모바일 앱 집중도를 웹에서도 유지한다

모바일과 웹에서 같은 정보 구조를 사용한다. 넓은 웹에서는 모바일 화면을 단순 확대하지 않고, 앱형 대화 화면을 중심에 두며 보조 정보만 좌우 패널로 확장한다.

## 3. 브랜드 성격과 시각 방향

### 3.1 브랜드 키워드

- 따뜻한 코치
- 신뢰할 수 있는 학습 파트너
- 문화적으로 세심함
- 명료함
- 부담 없는 도전

### 3.2 시각 방향

기존 화면 기획의 장점을 계승해 **따뜻한 아이보리 배경, 코발트 블루 포인트, 넓은 여백, 둥근 카드와 실사형 AI 페르소나**를 핵심 시각 언어로 사용한다. 코발트 블루는 주요 행동과 선택 상태에 집중하고, 감정 색상은 페르소나 상태와 분석 데이터에만 제한한다. 과도하게 유아적이거나 게임처럼 보이는 장식은 피하고 성인 학습자에게도 신뢰감을 주어야 한다.

### 3.3 기존 화면 기획에서 유지할 요소

- 실사형 페르소나를 주요 시각 요소로 사용하는 방식
- 따뜻한 아이보리 앱 배경과 흰색 카드의 대비
- 코발트 블루를 CTA, 선택 테두리, 활성 내비게이션에 사용하는 방식
- 둥근 카드, 배지, 바텀시트와 절제된 그림자
- 시나리오 카드의 난이도·소요 시간·목표 정보 구조
- 피드백을 대화 위 바텀시트로 확인하는 모바일 패턴
- 2열 페르소나 카드와 3개 이하의 단순한 하단 내비게이션

### 3.4 기존 화면 기획에서 보완할 요소

- 대화 화면에서 페르소나가 차지하는 높이를 줄이고 실제 메시지 영역을 확보한다.
- 의미가 모호한 삼각형 단독 버튼을 사용하지 않는다. `보내기`, `재생`, `대화 시작`을 각각 구분한다.
- `드래그로 높이 조절`을 기본 조작으로 요구하지 않는다. 페르소나 영역은 `축소/펼치기`로 제공한다.
- 한글 제목과 영문 제목을 붙여 쓰지 않는다. UI 기본 언어를 우선하고 영문은 보조 설명으로 분리한다.
- MVP에서 제외한 페르소나·시나리오 검색 UI를 노출하지 않는다.
- 잠금 상태만 보여주지 않고 로그인 또는 이용 조건과 다음 행동을 설명한다.
- 표현 피드백은 발음 점수보다 높임말·예의·맥락·자연스러움을 중심으로 구성한다.

## 4. 디자인 토큰

토큰 이름은 구현에서 CSS 변수, 테마 객체, 네이티브 디자인 토큰으로 동일하게 매핑한다.

### 4.1 색상

색상값의 단일 기준(Source of Truth)은 Figma `260820-1129` 파일(`G8GxBvtJDcALvKcGvaSHhH`)의 `01 Screen Plan 1.0` 페이지(`299:2165`) 안에 있는 `00 Foundations · Reusable Tokens` 섹션(`320:2`)과 `Foundation / Colors` 프레임(`320:5`)이다. 이 문서, Figma 변수, 실제 화면과 구현 코드는 아래 토큰 이름과 값을 동일하게 사용한다. 화면 노드에 HEX 값을 직접 입력하지 않고 해당 Figma 색상 변수를 바인딩한다.

Figma 1.0 화면의 디자인 시스템 검수 범위는 `01 인증·온보딩`, `02 홈·연습 탐색`, `03 대화 연습`, `04 면접 연습`, `05 결과·복습`, `06 내 정보`, `07 대화방 목록` 섹션으로 한정한다. `08 팝업 화면`과 `09 상태 화면 · Loading · Empty · Error · Partial` 섹션은 이번 디자인 시스템 기준과 색상 검수 범위에서 제외하며, 해당 섹션에만 존재하는 색상은 공식 토큰으로 간주하지 않는다.

### 4.2 타이포그래피

기본 서체는 한국어와 라틴 문자를 모두 안정적으로 지원하는 `Pretendard Variable`을 사용한다. 로드 실패 시 `Noto Sans KR`, 시스템 sans-serif 순으로 대체한다.

```css
font-family: "Pretendard Variable", "Noto Sans KR", -apple-system,
  BlinkMacSystemFont, "Segoe UI", sans-serif;
```

| 토큰 | 크기/행간 | 굵기 | 용도 |
| --- | --- | --- | --- |
| `type-display` | `32/42px` | 700 | 랜딩 핵심 문구 |
| `type-heading-1` | `28/38px` | 700 | 페이지 제목 |
| `type-heading-2` | `22/32px` | 700 | 섹션 제목 |
| `type-heading-3` | `18/28px` | 600 | 카드 제목 |
| `type-body-lg` | `17/28px` | 400 | 채팅 메시지, 주요 설명 |
| `type-body-md` | `15/24px` | 400 | 기본 본문 |
| `type-body-sm` | `13/20px` | 400 | 보조 설명 |

- 웹·앱 본문은 15px 미만으로 축소하지 않는다.
- 채팅 메시지는 학습 가독성을 위해 기본 17px을 사용한다.
- 한국어 문장에는 과도한 자간을 적용하지 않는다.
- 점수만 크게 표시하지 말고 반드시 평가 항목명과 해석을 함께 제공한다.

| `shadow-md` | `0 8px 24px rgba(35,33,30,.10)` | 떠 있는 패널 |
| `shadow-lg` | `0 20px 48px rgba(35,33,30,.14)` | 모달, 데스크톱 상세 패널 |

그림자보다 배경과 테두리로 구조를 먼저 구분한다.

### 4.6 아이콘

- 둥근 선형 아이콘을 기본으로 사용한다.
- 기본 크기는 20px, 작은 보조 아이콘은 16px, 핵심 음성 컨트롤은 24px 이상으로 한다.
- 아이콘 단독 버튼에는 접근성 이름과 툴팁을 제공한다.
- 마이크, 재생, 일시정지, 다시 듣기는 플랫폼 관습에 맞는 표준 아이콘을 사용한다.

### 4.7 모션

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `motion-fast` | `120ms` | 눌림, 호버 |
| `motion-normal` | `200ms` | 패널, 배지 전환 |
| `motion-slow` | `320ms` | 페르소나 감정 전환 |

- 녹음 중에는 1.2초 주기의 완만한 펄스를 사용할 수 있다.
- 페르소나 감정 이미지는 페이드 전환하며 갑작스러운 깜빡임을 금지한다.
- `prefers-reduced-motion`에서는 반복 애니메이션을 제거한다.

## 5. 반응형 레이아웃

### 5.1 브레이크포인트

| 이름 | 범위 | 기본 구성 |
| --- | --- | --- |
| Mobile | `0–767px` | 단일 컬럼, 하단 입력 고정 |
| Tablet | `768–1199px` | 단일 또는 2컬럼 전환 |
| Desktop | `1200px+` | 대화 중심 2~3영역 구성 |

### 5.2 페이지 폭

- 앱 셸 최대 폭: `1440px`
- 기본 콘텐츠 최대 폭: `1200px`
- 읽기·피드백 콘텐츠 최대 폭: `760px`
- 웹에서 앱형 단일 컬럼을 표시할 때 권장 폭: `390–480px`
- 모바일 좌우 안전 여백: `16px`
- 태블릿·데스크톱 좌우 여백: `24–40px`

웹에서 앱형 화면을 사용할 때는 `color-surface-web` 배경 위에 앱 셸을 중앙 배치한다. 앱 셸은 모바일 정보 구조를 유지하고, 최대 높이를 넘으면 내부 스크롤한다. 데스크톱 공간을 채우기 위한 장식 카드나 의미 없는 대시보드를 추가하지 않는다.

### 5.3 대화 화면 구성

#### 모바일

1. 상단: 뒤로가기, 페르소나 이름, 관계·상황 정보
2. 페르소나: 화면 높이의 약 `28–35%`, 축소 가능한 상단 영역
3. 메시지 목록: 최소 화면 높이의 `35%`를 확보한 세로 스크롤
4. 피드백: 메시지 아래 요약 카드 또는 바텀시트
5. 입력: 화면 하단 고정, 텍스트·마이크 전환

- 페르소나 이미지 아래에 큰 빈 영역을 남기지 않는다.
- 대화 시작 전에는 안내 문구를 표시하고, 첫 메시지 이후에는 채팅 영역이 공간을 사용한다.
- 페르소나 크기 조정은 자유 드래그보다 `축소/펼치기` 두 상태를 기본으로 한다.

#### 데스크톱

1. 왼쪽: 시나리오 목표와 관계 정보
2. 중앙: 페르소나와 채팅
3. 오른쪽: 현재 발화의 점수·피드백·감정 분석

오른쪽 패널이 닫힌 경우 중앙 대화 영역이 자연스럽게 확장되어야 한다.

## 6. 핵심 컴포넌트

### 6.1 버튼

#### 종류

- Primary: 대화 시작, 답변 보내기, 다음 단계
- Secondary: 다시 듣기, 자세히 보기, 다시 시도
- Tertiary: 취소, 접기, 부가 행동
- Destructive: 대화 삭제, 업로드 자료 삭제

#### 규칙

- 최소 높이 44px, 모바일 핵심 버튼은 48px을 권장한다.
- 로딩 중에는 라벨을 유지하고 스피너를 함께 표시한다.
- 비활성 상태에는 비활성 이유를 주변 문구로 설명한다.
- 한 화면에 Primary 버튼은 원칙적으로 하나만 둔다.
- 삼각형 아이콘 단독 버튼으로 전송과 재생을 함께 표현하지 않는다.
- `보내기`는 종이비행기 또는 화살표와 접근성 라벨, `재생`은 재생 아이콘과 `답변 듣기`, 녹음은 마이크와 `눌러서 말하기`로 구분한다.

### 6.2 입력창

- 기본, 포커스, 입력됨, 오류, 비활성 상태를 제공한다.
- 라벨은 placeholder로 대체하지 않는다.
- 오류 문구는 필드 바로 아래에 구체적으로 표시한다.
- 채팅 입력은 여러 줄을 지원하되 5줄 이후 내부 스크롤로 전환한다.

### 6.3 채팅 메시지

#### AI 메시지

- 왼쪽 정렬
- 중성 또는 브랜드 약한 배경
- 페르소나 이름, 메시지 본문, TTS 상태, 다시 듣기 제공
- 감정이 추정된 경우 작은 감정 라벨을 제공하되 대화 본문보다 강조하지 않는다.

#### 사용자 메시지

- 오른쪽 정렬
- 브랜드색 배경과 충분한 명도 대비
- STT 결과인 경우 `음성으로 입력됨` 라벨 제공
- 메시지별 `피드백 보기` 진입점을 제공

#### 메시지 상태

- 전송 중
- 전송 완료
- 응답 생성 중
- 실패 및 다시 시도
- TTS 생성 중
- 음성 재생 중

AI 응답 생성 중에는 빈 말풍선을 만들지 않고, `답변을 만들고 있어요` 상태 행을 사용한다.

### 6.4 음성 입력 컨트롤

| 상태 | 시각 표시 | 사용자 문구 |
| --- | --- | --- |
| 준비 | 마이크 아이콘 | `눌러서 말하기` |
| 권한 요청 | 안내 패널 | `마이크 사용을 허용해 주세요` |
| 듣는 중 | 파형·경과 시간·중지 버튼 | `듣고 있어요` |
| 변환 중 | 스피너 | `말한 내용을 글로 바꾸고 있어요` |
| 확인 | STT 텍스트 편집 가능 | `보내기 전에 확인해 주세요` |
| 실패 | 오류와 재시도 | `음성을 인식하지 못했어요` |
| 미지원 | 대체 입력 안내 | `이 브라우저에서는 텍스트로 입력해 주세요` |

녹음 시작과 종료는 색상뿐 아니라 아이콘, 라벨, 햅틱 또는 소리 중 가능한 수단으로 함께 알린다.

### 6.5 TTS 플레이어

- AI 텍스트가 표시된 직후 자동 재생을 시도한다.
- 브라우저 자동 재생 정책으로 차단되면 `눌러서 답변 듣기` 버튼을 즉시 보여준다.
- 재생·일시정지, 처음부터 다시 듣기, 재생 상태를 제공한다.
- 여러 메시지가 동시에 재생되지 않도록 한다.
- 사용자가 한 번 음소거하거나 자동 재생을 끄면 이후 선택을 존중한다.
- 텍스트는 음성 생성이나 재생 실패와 관계없이 먼저 읽을 수 있어야 한다.

### 6.6 페르소나

페르소나는 일러스트가 아닌 **실제 인물에 가까운 AI 생성 이미지**를 사용한다. MVP에서는 대화 중 이미지를 실시간 생성하지 않고, 동일 인물의 감정별 이미지를 사전에 생성한 뒤 감정 상태에 따라 교체한다.

#### 상태

- 기본/중립
- 기쁨
- 슬픔
- 화남
- 분석 중
- 이미지 로드 실패

#### 규칙

- 같은 페르소나는 감정이 바뀌어도 얼굴, 의상, 배경, 구도 등 정체성이 유지되어야 한다.
- 감정 이미지는 학습 맥락을 보조하며 사용자에게 위협적으로 보이지 않게 한다.
- `화남`은 공격성보다 불편함 또는 단호함 수준으로 표현한다.
- 이미지 아래에 페르소나 이름과 현재 관계를 텍스트로 표시한다.
- 이미지 생성 또는 로드 실패 시 기본 이미지와 감정 텍스트 라벨을 제공한다.

#### 이미지 스타일

- 자연스러운 인물 사진 스타일을 사용한다.
- 얼굴 또는 상반신 중심의 고정 구도와 단순한 배경을 사용한다.
- 과도한 피부 보정, 비현실적인 얼굴 비율, 공포감을 주는 표정을 피한다.
- 실제 인물, 유명인 또는 사용자의 동의 없는 특정 인물을 모방하지 않는다.
- 생성 이미지임을 서비스 정책 또는 관련 UI에서 명확하게 알린다.

#### 인물 일관성

감정별 이미지에서 다음 항목은 동일하게 유지한다.

- 얼굴형, 이목구비, 피부색과 나이대
- 머리 모양과 머리색
- 의상, 액세서리와 역할을 나타내는 소품
- 카메라 각도, 거리, 인물 크기와 이미지 비율
- 조명, 배경, 색온도와 사실감

감정 상태에 따라 바뀌는 요소는 표정, 눈썹과 눈의 형태, 입 모양, 시선과 미세한 자세로 제한한다.

#### 필수 이미지 세트

| 상태 키 | 표시 감정 | 표현 기준 |
| --- | --- | --- |
| `neutral` | 기본·중립 | 편안하고 주의 깊은 표정 |
| `happy` | 기쁨 | 과장되지 않은 자연스러운 미소 |
| `sad` | 슬픔 | 눈빛과 입꼬리가 약간 내려간 표정 |
| `angry` | 화남 | 위협적이지 않은 불편함 또는 단호함 |

#### 감정 매핑

```text
기쁨, 즐거움, 만족 → happy
슬픔, 실망 → sad
화남, 불쾌함, 짜증 → angry
보통, 궁금, 당황, 불확실, 분석 실패 → neutral
```

- 모델의 원본 감정값을 UI에서 직접 파일명으로 사용하지 않는다.
- 서버 또는 공용 매퍼에서 허용된 네 가지 상태로 정규화한다.
- 결과가 모호하거나 허용 목록에 없으면 `neutral`을 사용한다.
- TTS의 발화 감정과 이미지 표정은 같은 정규화 상태를 사용한다.

#### 파일 사양과 명명

- 원본 비율: `4:5`
- 권장 원본 크기: 최소 `1024×1280px`
- 웹 제공 형식: WebP 우선, AVIF 선택 지원
- 목록용 썸네일과 대화 화면용 이미지를 별도 크기로 최적화한다.
- 파일명은 영문 소문자와 하이픈을 사용한다.

```text
assets/personas/{persona-id}/
  neutral.webp
  happy.webp
  sad.webp
  angry.webp
```

#### 로딩과 전환

- 다음 감정 이미지를 미리 불러온 후 교체해 빈 화면을 방지한다.
- 감정 전환은 `200–320ms` 페이드로 처리하고 이미지 영역의 크기와 위치는 고정한다.
- 한 AI 메시지가 출력되는 동안 표정이 반복적으로 변경되지 않도록 한다.
- 이미지 로딩 실패, 분석 실패 또는 감정 이미지 누락 시 `neutral` 이미지로 복귀한다.
- 기본 이미지도 실패하면 인물 실루엣, 페르소나 이름과 감정 텍스트를 표시한다.
- 세부 생성·검수 절차는 `PERSONA_IMAGE_GUIDE.md`를 따른다.

### 6.7 시나리오 카드

필수 정보:

- 시나리오 제목
- 상대와의 관계
- 장소 또는 상황
- 대화 목표
- 예상 난이도
- 예상 시간
- `연습 시작` 행동

MVP에서는 자유 채팅, 기본 상황 시나리오, 이력서 기반 면접 시나리오를 서로 다른 카드 유형으로 구분한다.

- 카드 상단에 `추천`, 난이도, 예상 시간을 배치한다.
- 제목 아래에는 사용자가 달성할 대화 목표를 한두 줄로 설명한다.
- 진행 중인 카드는 `이어하기`, 미시작 카드는 `연습 시작` 행동을 제공한다.
- 잠긴 카드에는 `로그인 시 이용 가능`과 로그인 행동을 함께 제공한다.
- MVP에서는 검색 버튼을 표시하지 않는다.

### 6.8 관계·맥락 칩

예: `면접관`, `첫 만남`, `격식`, `부탁하기`, `중급`.

- 정보 표시용 칩과 선택 가능한 칩의 스타일을 구분한다.
- 한 화면에 너무 많은 칩을 노출하지 않는다.
- 색상보다 텍스트 의미가 먼저 읽히도록 한다.

### 6.8.1 페르소나 선택 카드

- 모바일에서는 2열 카드, 좁은 화면에서는 1열 전환을 허용한다.
- 실사형 썸네일, 이름, 사용자와의 관계, 대화 상황, 친밀도 또는 격식 수준을 표시한다.
- `캠퍼스 훈남`처럼 외모 중심의 모호한 설명보다 `같은 학교 선배`, `IT 기업 면접관`처럼 관계와 역할을 우선한다.
- 선택 상태는 코발트 블루 테두리, 체크 표시와 텍스트로 함께 표현한다.
- 잠긴 카드도 핵심 관계와 학습 목적을 읽을 수 있어야 하며 해제 조건을 안내한다.
- MVP에서는 검색 버튼을 표시하지 않는다.

### 6.9 파일 업로드

이력서·개인 데이터 기반 시나리오에서 사용한다.

- 허용 형식, 최대 크기, 데이터 사용 목적을 업로드 전에 표시한다.
- 업로드, 처리 중, 준비 완료, 실패 상태를 구분한다.
- 파일명과 삭제 버튼을 제공한다.
- `이 자료는 면접 시나리오 생성에만 사용됩니다`와 같은 목적 고지를 제공한다.
- AI가 문서에서 추출한 정보는 시작 전에 사용자가 확인·수정할 수 있어야 한다.

### 6.10 점수 컴포넌트

MVP 기본 평가 항목은 다음 네 가지로 통일한다.

| 항목 | 설명 | 표시 예시 |
| --- | --- | --- |
| 높임말·존댓말 | 관계에 맞는 높임 표현 | `높임말 20/25` |
| 예의와 배려 | 직접성, 완곡함, 인상 | `예의 21/25` |
| 맥락 적합성 | 상황·관계·목적과의 적합도 | `맥락 18/25` |
| 자연스러움 | 실제 한국어 표현의 자연스러움 | `자연스러움 22/25` |

#### 점수 표현

- 종합 점수와 항목별 점수를 함께 제공한다.
- 점수 구간에 `잘했어요`, `조금 더 연습해요` 같은 해석을 붙인다.
- 빨강·노랑·초록만으로 수준을 구분하지 않는다.
- 막대그래프에는 숫자와 항목명을 함께 제공한다.
- 점수 산정 실패 시 임의의 점수를 만들지 않고 설명형 피드백만 제공한다.

### 6.11 피드백 카드

피드백은 다음 순서를 따른다.

1. 한 줄 요약
2. 잘한 점
3. 개선할 점
4. 원래 표현
5. 추천 표현
6. 관계·맥락상 추천 이유
7. `추천 표현으로 다시 말하기`

#### 모바일 바텀시트

- 모바일에서는 대화 맥락을 유지하도록 피드백을 바텀시트로 표시할 수 있다.
- 접힌 상태에는 종합 점수, 한 줄 요약과 `자세히 보기`만 표시한다.
- 펼친 상태에는 항목별 점수, 잘한 점, 개선할 점, 원래 표현과 추천 표현을 순서대로 표시한다.
- 바텀시트는 화면의 최대 `85%`까지 확장하고 내부 스크롤을 제공한다.
- 피드백을 닫아도 대화와 입력 내용은 유지한다.

예시:

```text
잘한 점
요청 의도가 분명하고 존댓말을 사용했어요.

더 자연스럽게
원래 표현: 자료 빨리 주세요.
추천 표현: 가능하시면 자료를 오늘 중으로 보내주실 수 있을까요?
이유: 처음 만난 면접 담당자에게는 명령형보다 가능 여부를 묻는 표현이 더 부드러워요.
```

### 6.12 감정·인상 분석 카드

- 제목: `AI가 추정한 감정과 인상`
- 최대 세 가지 주요 감정을 비율과 함께 표시한다.
- 음성 분석이면 톤, 속도, 강세 등 관찰 근거를 제공할 수 있다.
- 텍스트 분석이면 실제 목소리를 들은 것처럼 설명하지 않는다.
- 성격, 정신 건강, 진실 여부 등 민감한 속성을 추론하지 않는다.
- 사용자가 분석이 다르다고 느끼면 `내 의도와 달라요` 피드백을 보낼 수 있게 한다.

### 6.13 토스트·배너·모달

- 토스트: 저장 완료처럼 짧고 되돌릴 수 있는 결과
- 인라인 배너: 마이크 미지원, TTS 지연처럼 현재 작업과 관련된 상태
- 모달: 파일 삭제, 대화 종료처럼 확인이 필요한 행동
- 시스템 오류는 사용자 탓으로 표현하지 않고 다음 행동을 제공한다.

## 7. 핵심 화면 패턴

### 7.1 온보딩

최소 입력만 받는다.

- 한국어 수준
- 학습 목적
- 자주 만나는 관계
- 선호 입력 방식
- 음성 자동 재생 여부

개인정보와 이력서는 온보딩에서 강제로 요구하지 않고 면접 시나리오 진입 시 목적과 함께 요청한다.

### 7.2 홈

우선순위:

1. 이전 대화 이어하기
2. 자유 채팅 시작
3. 상황별 시나리오
4. 이력서 기반 면접 연습
5. 최근 피드백 복습

### 7.3 대화 준비

- 페르소나와 사용자 관계
- 상황과 대화 목표
- 성공 조건
- 예상 시간
- 입력 방식
- 개인 자료 사용 여부

### 7.4 대화

대화 중에는 목표를 항상 짧게 확인할 수 있어야 한다. 페르소나 영역 아래에 실제 AI·사용자 메시지가 쌓이는 공간을 보장한다. 피드백은 각 사용자 발화 후 요약 카드로 제공하고 상세 내용은 바텀시트로 연다. 사용자가 연속 대화를 원하면 요약 카드도 자동으로 접을 수 있다.

### 7.5 결과와 복습

- 종합 점수
- 항목별 점수
- 잘한 표현
- 고쳐볼 표현 최대 3개
- 감정·인상 요약
- 대화 목표 달성 여부
- 다시 말하기
- 같은 상황 재도전

## 8. 상태와 예외 처리

모든 AI 기능은 다음 상태를 가져야 한다.

| 상태 | UI 원칙 |
| --- | --- |
| 초기 | 무엇을 할 수 있는지 설명 |
| 로딩 | 처리 대상과 진행 중인 작업을 구체적으로 표시 |
| 부분 성공 | 텍스트는 성공했지만 TTS가 실패한 경우처럼 가능한 결과부터 제공 |
| 빈 상태 | 다음 행동이 있는 안내 제공 |
| 오류 | 원인 범주와 재시도·대체 경로 제공 |
| 시간 초과 | 입력을 보존하고 재시도 제공 |
| 오프라인 | 네트워크 필요 기능과 로컬 가능 기능을 구분 |

### 8.1 대표 예외

- 마이크 권한 거부
- Web Speech API 미지원
- STT 결과 없음 또는 낮은 신뢰도
- Gemini 채팅 시간 초과
- ChatGPT 피드백 생성 실패
- TTS 생성 실패 또는 자동 재생 차단
- 감정 분석 실패
- 페르소나 이미지 로드 실패
- 이력서 업로드 실패 또는 지원하지 않는 형식
- RAG 처리 중 또는 검색 결과 없음

복합 파이프라인에서는 한 기능 실패가 전체 대화 실패로 보이지 않게 한다. 예를 들어 TTS가 실패해도 AI 텍스트 응답과 피드백은 유지한다.

## 9. 접근성

WCAG 2.2 AA 수준을 MVP 목표로 한다.

- 일반 텍스트 명도 대비는 최소 4.5:1을 확보한다.
- 큰 텍스트와 핵심 UI 그래픽은 최소 3:1을 확보한다.
- 모든 인터랙션은 키보드로 접근 가능해야 한다.
- 포커스 링을 제거하지 않는다.
- 터치 대상은 최소 44×44px로 한다.
- 텍스트 확대 200%에서도 기능과 정보가 손실되지 않아야 한다.
- 음성 콘텐츠에는 동일한 텍스트를 제공한다.
- 감정과 점수는 색상만으로 전달하지 않는다.
- 실시간으로 추가되는 AI 메시지 상태는 스크린리더에 과도하게 반복 안내하지 않는다.
- 자동 재생 음성은 즉시 일시정지할 수 있어야 한다.
- 이미지에는 인물의 감정과 역할을 설명하는 대체 텍스트를 제공한다.

## 10. 다국어와 콘텐츠 작성 규칙

- UI 기본 언어와 학습 대상 언어를 분리한다.
- 한국어 예문은 번역문 및 쉬운 설명과 함께 제공할 수 있어야 한다.
- 한국어를 잘못 사용했다는 이유로 사용자를 낮춰 말하지 않는다.
- `틀렸어요`보다 `이 상황에서는 이렇게 말하면 더 자연스러워요`를 우선한다.
- 문화적 차이는 절대 규칙이 아니라 맥락에 따른 경향으로 설명한다.
- 버튼은 가능한 한 동사형으로 쓴다: `대화 시작`, `다시 말하기`, `피드백 보기`.
- 로딩 문구는 실제 작업을 반영한다: `답변 생성 중`, `음성 만드는 중`, `표현 분석 중`.
- 기술명은 사용자에게 필요한 경우에만 노출한다. 일반 화면에서는 Gemini, RAG, STT 같은 용어보다 사용자 행동과 결과를 설명한다.

## 11. 개인정보와 신뢰 UI

- 이력서 업로드 전에 수집 목적, 보관 기간, 삭제 방법을 설명한다.
- 사용자가 자신의 자료와 생성된 시나리오를 삭제할 수 있어야 한다.
- AI가 만든 응답과 감정 분석에는 AI 생성·추정 정보임을 표시한다.
- 개인 데이터가 다른 사용자 시나리오에 사용된다는 인상을 주지 않는다.
- 파일 삭제나 전체 대화 삭제는 확인 절차를 거친다.
- 민감한 정보가 포함될 수 있는 이력서는 홈 화면 미리보기에서 내용을 노출하지 않는다.
