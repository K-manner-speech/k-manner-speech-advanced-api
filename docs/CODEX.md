# K-Manner Speech 공통 개발 규칙

이 문서는 이 프로젝트에서 작업하는 모든 구성원이 따라야 하는 공통 규칙이다.

## 1. 규칙의 우선순위

- 프로젝트의 기존 문서와 합의된 규칙을 개인의 선호보다 우선한다.
- 모든 작업은 `docs/` 폴더의 가이드 문서를 확인하고 그 내용을 따른다.
- 특히 코딩 컨벤션, Git·커밋 규칙, 프로젝트 구조, 디자인 시스템과 페르소나 이미지 가이드를 변경 범위에 맞게 적용한다.
- 문서끼리 충돌하거나 해석이 불분명하면 임의로 결정하지 말고 사용자에게 확인한다.

## 2. 아키텍처와 데이터 접근

- 핵심 비즈니스 로직은 서버에서 처리한다.
- 클라이언트에는 화면 표현, 사용자 입력, 상태 표시와 서버 API 호출에 필요한 책임만 둔다.
- 클라이언트는 데이터베이스에 직접 접근하지 않는다. 데이터 조회와 변경은 서버가 제공하는 API를 통해 수행한다.
- 인증과 권한 검사는 서버에서 수행하며, 사용자 소유 데이터는 검증된 사용자 ID를 기준으로 제한한다.
- 계층별 책임과 의존 방향은 `docs/PROJECT_STRUCTURE_V5.md`를 따른다.

## 3. 보안과 비밀값

- 비밀번호, API 키, 접근 토큰, 인증서, 데이터베이스 접속 정보 등 비밀값을 코드에 직접 작성하지 않는다.
- 비밀값은 환경 변수 또는 승인된 비밀 관리 수단으로 주입한다.
- 로컬 비밀 파일은 Git에 커밋하지 않는다. 필요한 환경 변수는 실제 값 없이 `.env.example`에 문서화한다.
- 비밀값과 개인정보를 로그, 오류 메시지, 테스트 데이터 또는 문서에 노출하지 않는다.
- 필수 보안 설정이 누락되면 위험한 기본값으로 동작하지 않고 명확하게 실패하도록 한다.

## 4. 구현과 변경 원칙

- 변경은 하나의 목적에 집중하고 가능한 한 작고 검토 가능한 단위로 나눈다.
- 단순하고 명시적인 구현을 우선하며, 불필요한 추상화와 과도한 최적화를 피한다.
- 구조 이동, 제품 용어 변경, API 변경과 도구 전환을 하나의 변경에 섞지 않는다.
- 생성 코드, 빌드 산출물과 사람이 관리하는 소스 코드를 구분한다.
- 코드, 설정 또는 실행 방법이 바뀌면 관련 문서와 예제도 함께 갱신한다.

## 5. 테스트와 검증

- 핵심 기능은 최소한 정상, 경계, 실패의 세 경우를 테스트한다.
- 버그를 수정할 때는 가능하면 동일 문제가 다시 발생하지 않도록 회귀 테스트를 추가한다.
- 외부 API, 현재 시간과 난수처럼 불안정한 요소는 테스트에서 제어 가능한 방식으로 대체한다.
- 작업을 완료하기 전에 변경 범위에 해당하는 Formatter, Linter, 정적 분석, 테스트와 빌드를 실행한다.
- 검증하지 못한 항목이 있으면 완료된 것처럼 표현하지 말고 이유와 남은 위험을 알린다.

## 6. 소통과 의사결정

- 사용자에게 진행 상황, 설명과 결과를 한국어로 전달한다.
- 구현상 결정을 내리면 선택한 내용과 이유를 짧게 기록한다.
- 큰 변경을 시작하기 전에는 영향 범위와 작업 계획을 먼저 사용자에게 보여주고 승인을 받은 뒤 진행한다.
- 큰 변경에는 아키텍처나 기술 스택 변경, API·데이터베이스 계약 변경, 대규모 파일 이동이나 이름 변경, 주요 의존성 교체, 호환성을 깨뜨리는 변경이 포함된다.
- 요구사항이 불명확하고 선택에 따라 결과가 크게 달라지면 임의로 범위를 넓히지 말고 사용자에게 확인한다.

## 7. Git과 리뷰

- `main`과 `develop`에 직접 커밋하거나 Push하지 않는다.
- 브랜치, 커밋, Pull Request와 병합 방식은 `docs/Git_Commit_Convention.md`를 따른다.
- 커밋 하나에는 하나의 논리적인 변경만 포함한다.
- 커밋 또는 PR 전에 변경 파일, 민감한 정보 포함 여부와 검증 결과를 확인한다.
- 리뷰에서는 요구사항 충족, 기존 동작 영향, 책임 분리, 보안, 오류 처리와 테스트를 우선 확인한다.

## 8. 완료 기준

작업은 다음 조건을 만족해야 완료로 본다.

- 요구사항과 `docs/`의 관련 규칙을 충족한다.
- 핵심 비즈니스 로직과 데이터 접근 경계가 서버에 유지된다.
- 비밀값이나 불필요한 민감 정보가 포함되지 않는다.
- 핵심 기능의 정상·경계·실패 테스트가 준비되고 관련 검증이 통과한다.
- 결정 사항과 그 이유, 수행한 검증, 남은 제한 사항을 한국어로 설명한다.
